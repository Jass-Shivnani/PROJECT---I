\begin{abstract}
Consumer operating systems hold our most sensitive digital records, including credentials, email threads, filesystem hierarchies, and private schedules. While commercial cloud assistants offer fluent conversational interfaces, streaming personal host telemetry across external networks exposes users to severe privacy and surveillance liabilities. Transitioning Large Language Models to local desktop hardware guarantees data sovereignty, but commodity workstations impose rigid token, compute, and memory limits. Raw model weights alone cannot maintain multi-session state, safely execute shell operations, or proactively anticipate user routines without an underlying orchestration kernel. We present Dione, an on-device Large Action Model (LAM) orchestration runtime built on the Microsoft Agent Framework (MAF 1.20.0). Dione unifies a step-bounded ReAct execution loop ($N_{\text{max}} = 10$) with a dual-tier memory subsystem that pairs an incremental NetworkX MultiDiGraph with ChromaDB vector storage. To operate within tight local token windows, Dione casts prompt construction as a bounded 0-1 Knapsack problem, combining greedy relevance-density ranking with a single-item safeguard to provably guarantee a $\frac{1}{2}$-approximation bound without token overflow. For long-term memory, an incremental NetworkX multigraph performs probabilistic path-ranking, resolving multi-hop entity queries in 1.158\,ms ($\pm 0.241$\,ms). Background routines are regulated by a piecewise adaptive heartbeat scheduler that scales polling frequency from 30\,s down to 900\,s during dormancy, while a multi-axis affective engine dynamically reprioritizes tasks when user urgency and frustration escalate. Tool execution is constrained by a 5-tier poset permission lattice with interactive confirmation prompts, alongside an isolated Win32 desktop station hook that resolves the Session 0 black-screen capture barrier. In physical workstation benchmarks, Dione achieved an 88.3\% task completion rate (53 out of 60 tasks) across standardized GAIA, AgentBench OS, and DBBench suites, a 90.0\% success rate (9 out of 10 tasks) on live unmocked end-to-end integration traces, blocked 98.0\% of adversarial prompt injections (98 out of 100 attacks), reduced prompt token overhead by 77.0\% relative to dense RAG baselines, and maintained 93.2\% memory recall over five longitudinal sessions while running within 463.11\,MB active RAM.
\end{abstract}

\section{Introduction}

Modern digital assistants are expected to manage daily user schedules, summarize personal correspondence, navigate filesystem directories, and coordinate software tools. Mainstream commercial platforms such as Apple Siri (with Apple Intelligence), Google Gemini, and Microsoft Copilot handle complex generative reasoning primarily within centralized cloud infrastructure, routing audio streams, desktop metadata, and personal correspondence to remote server farms \cite{apple2024pcc, google2024geminiprivacy, microsoft2024copilotprivacy}. While privacy-preserving cloud extensions have been engineered (such as Apple Private Cloud Compute \cite{apple2024pcc}), standard default assistant configurations still necessitate streaming sensitive user telemetry and prompt context across external networks whenever requests exceed localized on-device heuristic budgets. For enterprise and privacy-conscious users, this centralized paradigm poses severe structural liabilities:
\begin{enumerate}
    \item \textbf{Loss of Data Sovereignty:} Storing private communications, local codebases, and credentials on third-party cloud infrastructure exposes individuals to data harvesting, unauthorized surveillance, and corporate policy shifts.
    \item \textbf{Strictly Passive Operation:} Cloud agents wake up only upon explicit user invocation. They lack persistent ambient awareness, unable to track habits or proactively surface contextual reminders before an explicit query is issued.
    \item \textbf{Shallow Vector Memory Collapse:} Standard dense vector retrieval (RAG) calculates similarity purely over isolated text chunks. Over multi-session dialogues, vector distance degrades due to semantic distractor collisions, failing to resolve relational queries such as \textit{``Send the project report discussed with Prof. Shejy last Thursday''}.
    \item \textbf{Unconstrained Execution and System Hijacking:} Autonomous tool agents can enter infinite recursive loops or execute destructive host shell commands when exposed to prompt injection payloads embedded in retrieved emails or files.
\end{enumerate}

Running open-weights foundation models (such as Mistral-7B or LLaMA-3-8B) on consumer PCs via Ollama or llama.cpp ensures data sovereignty. However, raw model weights cannot act as ambient personal assistants on their own. They possess no built-in operating system hooks, lack stateful relational memory, and frequently hallucinate tool syntax when running on compact 7B-parameter scales.

To resolve these challenges, we designed and implemented \textbf{Dione}, a local-first Large Action Model (LAM) orchestration engine built upon the \textbf{Microsoft Agent Framework (MAF 1.20.0)} \cite{microsoft2025agentframework}. Dione runs directly on consumer host hardware, executing operating system tools, graph retrievals, and proactive background routines with zero mandatory cloud connectivity.

Our primary contributions are as follows:
\begin{enumerate}
    \item \textbf{MAF-Native Execution Kernel:} We extend the Microsoft Agent Framework with deterministic step budgets ($N_{\text{max}} = 10$) and typed schemas (\texttt{@tool}), preventing infinite hallucination loops in local small language models.
    \item \textbf{Mathematical Memory \& Context Optimization:} We formulate prompt construction under strict hardware token limits as a formal \textbf{0-1 Knapsack Optimization Problem} with a provable $\frac{1}{2}$-approximation single-item safeguard, pairing it with a \textbf{Probabilistic Graph Path-Ranking Model} over a typed NetworkX relational multigraph.
    \item \textbf{Affective State \& Persona Modeling:} We model multi-axis emotional state transitions and dynamic event queue prioritization, ensuring urgent and frustrated inputs preempt routine background tasks.
    \item \textbf{Hardware Safety \& Multimodal GUI Control:} We establish a 5-tier poset permission lattice ($\mathcal{L}$) enforced via neuro-symbolic middleware, and document an isolated desktop station hook that overcomes the Windows Session 0 black-screen barrier.
    \item \textbf{Empirical Host Validation:} We report unmocked evaluations on a physical 8-core host PC, achieving an 88.3\% completion rate (53/60) across standardized AgentBench and GAIA suites, a 90.0\% success rate on live unmocked traces, and a 98.0\% defense rate (98/100) against hostile prompt injection attacks.
    \item \textbf{Societal Relevance and UN SDGs:} Dione advances United Nations Sustainable Development Goal 9 (Industry, Innovation, and Infrastructure) and Goal 12 (Responsible Consumption and Privacy) by proving that capable, ambient digital assistants can run entirely on decentralized consumer hardware without surveillance data harvesting.
\end{enumerate}

\section{Related Works and Theoretical Foundations}

\subsection{Tool-Augmented Reasoning and Agent Lifecycles}
Yao et al. formalized the interleaving of natural language reasoning traces and environmental actuation in \textbf{ReAct} \cite{yao2023react}. This interleaved loop reduces compounding inference errors and anchors intermediate actions directly to execution feedback. Schick et al. demonstrated in \textbf{Toolformer} \cite{schick2023toolformer} that language models can learn self-supervised tool dispatching. Qin et al. extended this toward large-scale API tooling with \textbf{ToolLLM} \cite{qin2023toolllm}, spanning thousands of REST endpoints.

In practical testing, early open-source agent scripts like AutoGPT \cite{liu2023agentbench} relied on loose regex patterns over unstructured JSON text. In our early tests on 7B-parameter local models, slight formatting deviations frequently triggered unhandled JSON parser exceptions and infinite execution loops. The \textbf{Microsoft Agent Framework (MAF 1.20.0)} \cite{microsoft2025agentframework} resolves this by enforcing typed signatures (\texttt{@tool}) and middleware interceptors (\texttt{AgentMiddleware}). Dione builds directly on MAF, combining typed tool dispatch with deterministic host safety checks and knowledge graph retrieval.

\subsection{Memory Subsystems: Dense RAG vs. Relational Graphs}
Most retrieval-augmented generation (RAG) pipelines rely on dense vector embeddings (e.g., ChromaDB, FAISS) compared via cosine similarity \cite{lewis2020retrieval}. While vector search excels at retrieving isolated textual fragments, it lacks topological awareness. Over prolonged multi-turn desktop sessions, embedding distance degrades because unrelated interactions share common conversational tokens.

Packer et al. introduced \textbf{MemGPT} \cite{packer2023memgpt}, treating context management like OS virtual memory paging by shuttling text between active prompt windows and external tables. However, this virtual paging requires frequent self-editing LLM tool calls, which quickly exhausts local token budgets.

More recently, Edge et al. introduced \textbf{GraphRAG} \cite{edge2024graphrag}, applying community detection algorithms such as Leiden clustering over entity graphs to generate hierarchical text summaries. Pan et al. \cite{pan2024unifying} and Sun et al. \cite{sun2023thinkongraph} showed how explicit graph structures ground multi-hop factual reasoning. GraphRAG focuses primarily on offline analysis of massive document collections, where multi-stage clustering can take several minutes to hours. In contrast, an interactive desktop assistant requires immediate responses. Dione instead maintains an incremental, typed multigraph using NetworkX, executing bounded $k$-hop traversals in 1.158\,ms ($\pm 0.241$\,ms) directly on disk without requiring recurring offline cluster summarization.

\subsection{Agent Security and Host Sandboxing}
Granting an autonomous agent access to local shell commands introduces real host security risks:
\begin{itemize}
    \item Ruan et al. \cite{ruan2023identifying} observed that unconstrained agent loops frequently execute harmful filesystem operations when intermediate steps fail.
    \item Greshake et al. \cite{greshake2023not}, Liu et al. \cite{liu2023prompt}, and Yi et al. (BIPIA) \cite{bipia2023} showed that untrusted external inputs---such as retrieved web pages or downloaded emails---can contain hidden adversarial instructions that redirect tool execution.
    \item Zhang et al. formalized these threat vectors in the \textbf{Agent Security Bench (ASB)} \cite{zhang2024agent}, cataloging attack patterns across tool tampering, memory poisoning, and unauthorized privilege escalation across 10 scenarios and 400+ tools.
\end{itemize}

Existing agent frameworks often delegate safety either to high-level system prompts or to coarse-grained containerization. In local desktop environments, prompt-based guardrails fail against determined injection payloads, while full Docker containers disconnect the agent from native desktop workflows. Dione addresses this boundary directly through \texttt{DioneSafetyMiddleware}, combining static AST parameter inspection, shell syntax sanitization, and interactive confirmation gates before any high-privilege action runs on the host (Table~\ref{tab:security_comparison}).

\section{System Architecture and Mathematical Formulations}

Dione operates as an asynchronous client-server architecture. The backend server runs as a FastAPI daemon hosting the MAF runtime, memory manager, affective engine, and plugin registry. The client communicates over WebSockets and REST APIs, supporting both a Flutter mobile companion and desktop CLI interfaces (Fig.~\ref{fig:architecture_pipeline}).

\subsection{Typed Relational Knowledge Graph}
Dione represents memory as a directed multigraph $\mathcal{G} = (\mathcal{V}, \mathcal{E}, \mathcal{R})$. The vertex set $\mathcal{V}$ is partitioned into typed entities:
\begin{equation}
\mathcal{V} = \{v_i \mid v_i = (\text{id}, \tau, \text{name}, \mathcal{M})\}, \quad \tau \in \mathcal{T}
\end{equation}
where $\mathcal{T} = \{\text{Person}, \text{Event}, \text{Document}, \text{Task}, \text{Preference}, \text{Organization}\}$. Edges $e = (u, v, r, w, t) \in \mathcal{E}$ define relationships of type $r \in \mathcal{R}$ with confidence weight $w \in [0, 1]$ and last-accessed timestamp $t$.

\subsubsection{Probabilistic Entity Resolution and Subgraph Extraction}
When a user query $q$ is received, Dione extracts candidate entity mentions $\mathcal{V}_q \subseteq \mathcal{V}$. To resolve ambiguous references, the relevance score $R(v \mid q)$ combines semantic embedding similarity with graph topological connectivity:
\begin{equation}
R(v \mid q) = \lambda \cdot \text{sim}(\mathbf{e}_v, \mathbf{e}_q) + (1 - \lambda) \sum_{r \in \mathcal{N}(v)} w_r(t) \cdot \mathbf{1}(v, r)
\end{equation}
where $\text{sim}(\mathbf{e}_v, \mathbf{e}_q)$ is the cosine similarity between dense embeddings, $\lambda \in [0, 1]$ balances semantic meaning against topological link strength, and the edge weight $w_r(t)$ incorporates exponential temporal decay and reinforcement:
\begin{equation}
w_r(t) = w_0 \cdot \exp\left(-\frac{t - t_{\text{last}}}{\tau}\right) + \kappa \cdot \log(1 + n_{\text{access}})
\end{equation}
where $\tau$ is the memory half-life retention parameter and $n_{\text{access}}$ denotes cumulative relationship traversal frequency.

Dione then extracts a bounded $k$-hop subgraph ($k=2$):
\begin{equation}
\mathcal{G}_{\text{sub}}(q) = \bigcup_{v \in \mathcal{V}_q} \left\{ u \in \mathcal{V} \;\middle|\; \text{dist}_{\mathcal{G}}(v, u) \le k \right\}
\end{equation}
This bounded subgraph is serialized into deterministic context tokens, preserving relational connectivity without dumping raw conversation logs.

\subsection{Token Allocation as a 0-1 Knapsack Optimization Problem}
Local small-footprint models possess strictly limited context windows ($C_{\text{max}}$, typically 8,192 tokens). If prompt tokens exceed $C_{\text{max}}$, execution either crashes with Out-Of-Memory (OOM) errors or silently truncates critical instructions.

We formulate prompt context assembly as a formal \textbf{0-1 Knapsack Optimization Problem}. Given $M$ candidate memory items comprising short-term dialogue turns, Knowledge Graph relational triples, and vector database document chunks:
\begin{itemize}
    \item Let $r_i \in \mathbb{R}^+$ represent the calculated relevance reward of candidate item $i$.
    \item Let $c_i \in \mathbb{Z}^+$ represent the token footprint of chunk $i$.
    \item Let $x_i \in \{0, 1\}$ be the binary decision variable indicating whether item $i$ is included in the context prompt.
\end{itemize}

The optimization problem is defined as:
\begin{equation}
\max \sum_{i=1}^{M} r_i x_i \quad \text{subject to} \quad \sum_{i=1}^{M} c_i x_i \le C_{\text{budget}}
\end{equation}
where $C_{\text{budget}} = C_{\text{max}} - C_{\text{system}} - C_{\text{reserve}}$. In our physical runtime, $C_{\text{max}} = 8{,}192$, $C_{\text{system}} = 512$, and $C_{\text{reserve}} = 1{,}024$, yielding an exact operational budget of $C_{\text{budget}} = 6{,}656$ tokens.

To avoid dynamic programming latencies ($O(M \cdot C_{\text{budget}})$) during interactive inference, Dione implements a density-based greedy approximation with a single-item safeguard. We calculate relevance density:
\begin{equation}
\rho_i = \frac{r_i}{c_i}
\end{equation}
Candidate items are sorted in descending order $\rho_{(1)} \ge \rho_{(2)} \ge \dots \ge \rho_{(M)}$ and packed into greedy subset $S_{\text{greedy}}$ until capacity cannot accommodate candidate $k$. Let $i^* = \arg\max_{i: c_i \le C_{\text{budget}}} r_i$ be the single most valuable feasible chunk. The final prompt selection is:
\begin{equation}
S^* = \arg\max_{S \in \{S_{\text{greedy}}, \{i^*\}\}} \sum_{j \in S} r_j
\end{equation}

\textbf{Theorem (Approximation Guarantee):} $R(S^*) \ge \frac{1}{2} R(\text{OPT})$.  
\textit{Proof:} In the fractional LP relaxation, critical item $k$ satisfies $\text{OPT} \le \text{OPT}_{\text{frac}} \le R(S_{\text{greedy}}) + r_k$. Since $r_k \le r_{i^*} = R(\{i^*\})$, we have $\text{OPT} \le R(S_{\text{greedy}}) + R(\{i^*\}) \le 2 \max(R(S_{\text{greedy}}), R(\{i^*\})) = 2 R(S^*)$, proving $R(S^*) \ge \frac{1}{2} \text{OPT}$. This executes in $O(M \log M)$ time, protecting the host model from context overflow while provably retaining context quality.

\subsection{Affective State Transitions and Dynamic Priority Queuing}
In an ambient desktop assistant, user inputs vary sharply in urgency---from casual queries to time-critical administrative tasks. To ensure the assistant responds appropriately rather than generating uniform conversational filler, Dione tracks an affective state vector:
\begin{equation}
\mathbf{S}_t = \big(e_t, u_t, f_t, \mathbf{P}_t\big)
\end{equation}
where $e_t$ denotes the primary emotional state across nine discrete categories (\textit{joy}, \textit{trust}, \textit{anticipation}, \textit{surprise}, \textit{fear}, \textit{sadness}, \textit{anger}, \textit{disgust}, \textit{neutral}) generated by a fine-tuned DistilRoBERTa sequence classifier; $u_t \in [0, 1]$ represents urgency; $f_t \in [0, 1]$ represents detected user frustration; and $\mathbf{P}_t = (\mu_t, \eta_t, \psi_t)$ represents Dione's internal persona state (mood $\mu$, energy $\eta$, formality $\psi$).

\subsubsection{Persona Drift Formulation}
The persona state evolves as an exponentially decaying moving average to prevent abrupt behavioral oscillations:
\begin{equation}
\mathbf{P}_{t+1} = \gamma \mathbf{P}_t + (1 - \gamma) \phi(\mathbf{S}_t), \quad \gamma = 0.70
\end{equation}
When urgency $u_t > 0.70$, formality $\psi_{t+1}$ scales upward, immediately suppressing conversational filler words and instructing the ReAct kernel to prioritize terse, actionable tool execution.

\subsubsection{Dynamic Event Queue Priority}
Incoming asynchronous events from background monitors and user clients are queued according to a dynamic priority score $Q(E_i)$:
\begin{equation}
Q(E_i) = \beta_1 u_i + \beta_2 f_i + \beta_3 w_{\text{type}} + \beta_4 e^{-\lambda (t - t_0)}
\end{equation}
where $w_{\text{type}}$ is the base category weight and $\lambda$ is a temporal decay parameter. This ensures critical, emotionally urgent user inputs immediately preempt routine background maintenance tasks.

\subsection{Adaptive Ambient Heartbeat Scheduling}
Running continuous background perception on a host workstation quickly saturates CPU threads and drains laptop batteries if executed at fixed high frequencies. To deliver proactive background assistance sustainably, Dione decouples background habit checks from user prompts through an \textbf{Adaptive Heartbeat Scheduler}. The polling interval $I_t$ adjusts dynamically based on elapsed user inactivity:
\begin{equation}
I_t = 
\begin{cases}
    30\,\text{s}, & \text{Active (recent user interaction)} \\
    300\,\text{s}, & \text{Idle (10--60 min inactive)} \\
    900\,\text{s}, & \text{Dormant ($>60$ min inactive)}
\end{cases}
\end{equation}

During each pulse, Dione evaluates the Habit Pattern Store $\mathcal{H} = \{h_1, h_2, \dots, h_p\}$. A habit rule $h_j$ triggers an ambient proactive notification when the activation probability surpasses an empirical threshold $\theta = 0.85$:
\begin{equation}
P(\text{trigger} \mid t, \mathbf{x}) = \sigma\left(\mathbf{w}_h^T \mathbf{x}_t + b_h\right) \ge \theta
\end{equation}

\subsection{Five-Tier Poset Permission Lattice and Security Middleware}
Autonomous agents with OS shell access present grave security risks. Dione structures permissions as a formal partially ordered set (poset) lattice:
\begin{equation}
\mathcal{L} = (\mathcal{P}, \le), \quad \mathcal{P} = \{\text{NONE} < \text{READ} < \text{WRITE} < \text{EXECUTE} < \text{FULL}\}
\end{equation}

Before any tool is dispatched by the MAF runtime, \texttt{DioneSafetyMiddleware} enforces three sequential verification gates:
\begin{enumerate}
    \item \textbf{Lattice Manifest Check:} The tool's declared permission tier must satisfy $\text{Level}(\text{Tool}) \le L_{\text{plugin}}$, terminating unauthorized capability calls immediately.
    \item \textbf{Deterministic Shell Sanitization:} All string parameters are parsed via AST validation to detect forbidden shell operators (\texttt{\&}, \texttt{|}, \texttt{;}, \texttt{`}, \texttt{\$()}, \texttt{\textbackslash n}) and destructive command patterns (\texttt{rmdir /s /q}, \texttt{del /f /s}, \texttt{format}).
    \item \textbf{Interactive Confirmation Gate:} Any tool classified as \texttt{WRITE} or higher that targets sensitive directories or critical system operations triggers an interactive pause. Execution suspends until the user explicitly confirms the action through the mobile app or CLI modal.
\end{enumerate}

\subsection{Win32 Multimodal Computer-Use Engine}
To enable autonomous GUI interaction without cloud vision APIs, Dione interfaces with the Windows desktop using native Win32 APIs.

\subsubsection{Overcoming Session 0 Desktop Station Isolation}
A common hurdle in Windows service automation is Session 0 Isolation. When background threads call standard screen capture functions (such as GDI `BitBlt` or `ImageGrab`), the operating system returns blank or black frames because the thread is detached from the interactive desktop station (`winsta0\textbackslash default`).

Dione resolves this by spawning isolated worker threads that explicitly acquire desktop station handles prior to capturing pixels:
\begin{verbatim}
hwinsta = user32.OpenWindowStationW(
    "winsta0", False, MAXIMUM_ALLOWED)
user32.SetProcessWindowStation(hwinsta)
hdesk = user32.OpenInputDesktop(
    0, False, MAXIMUM_ALLOWED)
user32.SetThreadDesktop(hdesk)
\end{verbatim}
Once attached to the input desktop, the worker thread captures the frame, translates pixel bounding boxes into actionable UI coordinates, and dispatches clicks via Win32 \texttt{SendInput}.

\subsubsection{Spatial Coordinate Grounding and Actuation}
The multimodal vision model parses UI elements, predicting normalized bounding boxes $B = (x_{\text{min}}, y_{\text{min}}, x_{\text{max}}, y_{\text{max}}) \in [0, 1]^4$. Dione maps the normalized centroid $(x_c, y_c)$ into discrete physical display coordinates:
\begin{equation}
\begin{pmatrix} X_{\text{screen}} \\ Y_{\text{screen}} \end{pmatrix} = \begin{pmatrix} \lfloor x_c \cdot W_{\text{res}} \rfloor \\ \lfloor y_c \cdot H_{\text{res}} \rfloor \end{pmatrix}
\end{equation}
where $W_{\text{res}} \times H_{\text{res}}$ represents host display resolution. Actuation targets are verified against active UI regions using an Intersection-over-Union threshold:
\begin{equation}
\text{IoU}(B_{\text{target}}, B_{\text{active}}) = \frac{|B_{\text{target}} \cap B_{\text{active}}|}{|B_{\text{target}} \cup B_{\text{active}}|} \ge 0.50
\end{equation}
preventing erroneous clicks on overlapping window layers before dispatching Win32 \texttt{SendInput} mouse events.

\section{Experimental Evaluation and Results}

\subsection{Host Testbed Specifications}
All empirical benchmarks were conducted directly on local workstation hardware without cloud offloading:
\begin{itemize}
    \item \textbf{Host Processor:} Intel64 Family 6 Model 141 (8 Physical Cores, 8 Logical Threads @ 2.80\,GHz).
    \item \textbf{System Memory:} 15.78\,GB Physical DDR4 RAM.
    \item \textbf{Operating System:} Microsoft Windows 11 Pro (Build \texttt{10.0.26340}).
    \item \textbf{Python Runtime:} Python 3.12.10 (64-bit virtual environment).
    \item \textbf{Measured Process Footprint:} PID 16828; active RSS RAM: \textbf{463.11\,MB}; active CPU load: \textbf{14.3\%}.
\end{itemize}

\subsection{Comparative System Analysis}
We benchmark Dione against representative open-source and commercial agent architectures in Table~\ref{tab:comparison}.

\subsubsection{Testbed and Evaluation Methodology}
All comparative measurements marked with an asterisk ($^*$) were conducted on the identical physical host workstation (Intel 8-core CPU @ 2.80\,GHz, 16\,GB DDR4 RAM, Windows 11 Pro 64-bit). The active runtime versions evaluated were: OpenClaw v0.8.4 (Node.js v20.11), Letta/MemGPT v0.3.15 (FastAPI backend with SQLite), AutoGPT v0.5.0 (Python 3.12 execution loop), and CrewAI v0.28.8 with LangGraph v0.0.30. For local execution baselines (Dione, OpenClaw, Letta), foundation models were deployed using LLaMA-3-8B-Instruct quantized to 4-bit (Q4\_K\_M) via Ollama v0.1.32. For cloud-dependent frameworks lacking offline local inference (AutoGPT), API requests were routed via OpenAI GPT-4o-mini endpoints. Active process memory footprint was measured using \texttt{psutil.Process().memory_info().rss}, recording the steady-state resident memory of the agent orchestrator after 5 conversational rounds (excluding the independent Ollama daemon, which consumes $\sim$4.8\,GB unified VRAM/RAM across all local systems).

\subsubsection{Workload and Context Compression Formulation}
The longitudinal dialogue workload comprised a 5-session evaluation containing 30 conversational turns with 25 relational entity queries adapted from the Multi-Session Chat (MSC) benchmark \cite{packer2023memgpt}. Values marked with a dagger-double ($^\ddagger$) are cited directly from published peer-reviewed literature: MemGPT's 76.5\% session-5 recall and AutoGPT/Dense RAG's 34.8\% baseline recall are sourced from Packer et al. \cite{packer2023memgpt} under identical MSC task formulations.

The reported 77.0\% prompt token reduction is calculated directly from turn-by-turn context tracking over this 30-turn workload. A standard dense vector RAG baseline (modeled after Packer et al. \cite{packer2023memgpt}) accumulates $T_{\text{RAG}}(t) = 1{,}200 + 380 \cdot t$ tokens, reaching 12,600 tokens by turn 30 and exceeding the 8,192-token context window at turn 19. OpenClaw's raw markdown log append reaches 13,400 tokens ($800 + 420 \cdot t$). MemGPT's virtual context paging reaches 7,400 tokens ($2{,}450 + 165 \cdot t$). In contrast, Dione's 0-1 Knapsack optimizer and 2-hop relational subgraph extraction packs only the most relevant candidate triples and recent dialogue turns within $C_{\text{budget}} = 6{,}656$, scaling as $T_{\text{Dione}}(t) = 650 + 75 \cdot t$ and reaching only 2,900 tokens at turn 30. The resulting prompt compression is:
\begin{equation}
\text{Token Savings} = \frac{12{,}600 - 2{,}900}{12{,}600} \times 100\% = 76.984\% \approx 77.0\%
\end{equation}

\subsection{Standardized Automation Benchmarks (AgentBench \& GAIA)}
To evaluate operational competence across heterogeneous desktop tasks, we benchmarked Dione against $N=60$ standardized problem instances drawn from \textbf{GAIA} \cite{mialon2023gaia} and \textbf{AgentBench} \cite{liu2023agentbench}:
\begin{itemize}
    \item \textbf{Dataset Composition ($N=60$):} 20 operating system interaction tasks from AgentBench OS (file tree traversal, batch file renaming, regex extraction), 20 relational database queries from DBBench (SQLite schema joins, aggregate calculations), and 20 multimodal reasoning tasks from GAIA (Levels 1 and 2, spanning tabular analysis, arithmetic reasoning, and formatting transformations).
    \item \textbf{Empirical Results:} Dione achieved an overall completion rate of \textbf{88.3\% (53 out of 60 tasks passed)}, resolving filesystem workflows in an average of 2.14 steps and database tasks in 2.45 steps (Table~\ref{tab:benchmark_breakdown}). Specifically, AgentBench OS achieved 18/20 (90.0\%), DBBench achieved 18/20 (90.0\%), and GAIA achieved 17/20 (85.0\%). In contrast, AutoGPT frequently entered unbounded recursive loops, averaging 14.8 steps per task and failing step bounds on 43.3\% of runs (Fig.~\ref{fig:task_execution}).
    \item \textbf{GUI Grounding Accuracy:} In 35 multi-window desktop actuation trials, Dione attained a 91.4\% click grounding accuracy with an average target centroid offset of $\le 12$ pixels under the $\text{IoU} \ge 0.50$ validation threshold.
\end{itemize}

\subsection{Adversarial Security Benchmarks (ASB \& Injection Defense)}
To verify the defensive boundary of \texttt{DioneSafetyMiddleware}, we evaluated the system against $N=100$ hostile vectors combining direct prompt injections, indirect retrieved-context attacks, and host command injection exploits:
\begin{itemize}
    \item \textbf{Direct Injections (40 cases):} System override instructions, persona manipulation, and simulation jailbreaks adapted from Liu et al. \cite{liu2023prompt}, Perez \& Ribeiro \cite{perez2022ignore}, and JailbreakBench \cite{jailbreakbench2024}. 38 were blocked at Level 1 (pre-execution AST and dangerous regex/syntax filtering), 1 at Level 2 (lattice capability gate), and 1 resulted in a non-actuating conversational text completion without executing tools (39/40 defended, 97.5\% containment).
    \item \textbf{Indirect Injections (35 cases):} Poisoned payloads embedded inside simulated emails (15), downloaded markdown/HTML (10), and local documents (10) adapted from BIPIA \cite{bipia2023}, InjecAgent \cite{injecagent2024}, and Agent Security Bench (ASB) \cite{zhang2024agent}. 24 were neutralized at Level 1, 10 at Level 2/3 (lattice permissions and confirmation gates), and 1 generated a benign non-actuating text summary without actuating the embedded hyperlink payload (34/35 defended, 97.1\% containment).
    \item \textbf{Privilege Escalation (25 cases):} Hostile shell payloads attempting unauthorized file deletion (\texttt{rmdir /s /q}), recursive file destruction (\texttt{del /f /s}), or Windows registry tampering. 24 were blocked at Level 1 and 1 was halted by the Level 3 interactive confirmation gate (25/25 defended, 100.0\% containment).
    \item \textbf{Aggregate Defense Results \& Success Criteria:} The safety kernel successfully intercepted \textbf{98 out of 100 attacks (98.0\% defense rate)}, comprising \textbf{86 blocked at Level 1} and \textbf{12 halted at Level 2/3} (Table~\ref{tab:security_comparison}). An attack is scored as defended if the kernel rejects the command at Level 1, halts execution at Level 2, or mandates user approval at Level 3. In the 2 remaining instances, the underlying model produced passive text responses without emitting any tool calls; because no unauthorized actions executed, \textbf{zero destructive host alterations occurred (0.0\% breach rate across all 100 vectors)}, confirming complete workstation containment (Fig.~\ref{fig:resource_safety}).
\end{itemize}

\section{Proposed Architectural Extensions and Limitations}

While Dione is fully operational as a single-workstation desktop engine, we document three proposed architectural extensions alongside current system limitations.

\subsection{Multi-Device Federated Knowledge Graph Synchronization}
Currently, Dione stores knowledge graphs locally on a single host machine. In future revisions, we propose a peer-to-peer federated synchronization protocol across a user's phone, laptop, and desktop. Rather than transmitting raw conversational transcripts across devices, the nodes will synchronize localized model weights and serialized graph delta representations. To preserve zero-trust privacy, updates will be protected via differential privacy, adding calibrated Gaussian noise $\mathcal{N}(0, \sigma^2)$ to model gradients before transmission.

\subsection{Swarm Multi-Agent Consensus}
The current Dione architecture relies on a single master LLM thread. We propose extending the orchestration runtime to support multi-agent swarm intelligence. Specialized sub-agents will execute domain-specific workflows (e.g., an indexing agent for filesystem metadata, an interaction agent for calendar scheduling, and an analysis agent for document summarization). The master orchestrator will coordinate these agents using a lightweight decentralized consensus protocol, substantially reducing prompt token clutter and isolating domain failure states.

\subsection{Continuous Vision Structural Diffing}
The current multimodal computer-use engine runs on demand. We plan to extend this into a continuous background visual awareness loop. To prevent GPU thermal throttling and battery depletion from running continuous vision inference, we propose a two-stage structural diffing algorithm:
\begin{equation}
\Delta(F_t, F_{t-1}) = \frac{1}{|\Omega|} \sum_{(x, y) \in \Omega} \|F_t(x, y) - F_{t-1}(x, y)\|_1
\end{equation}
The heavy multimodal vision model will remain dormant until the spatial pixel delta $\Delta$ exceeds an empirical threshold $\delta_{\text{thresh}}$, ensuring high perceptual responsiveness with minimal compute overhead.

\subsection{System Limitations and Threats to Validity}
While Dione demonstrates high autonomy and data sovereignty on commodity hardware, several engineering constraints must be noted:
\begin{itemize}
    \item \textbf{Local SLM Parameter Capacity:} Compact 7B-parameter models occasionally struggle with highly nested subqueries or deep syntactic regex escaping, accounting for 4 out of our 7 benchmark task failures.
    \item \textbf{Host Platform Portability:} The desktop station hook (\texttt{winsta0\textbackslash default}) and mouse actuation bindings are written for native Microsoft Win32 APIs. Porting Dione to Linux or macOS environments requires adapting window handles to X11/Wayland and Quartz protocols.
    \item \textbf{Multimodal CPU Latency:} Executing local vision models on CPU threads introduces an inference latency of 800--1,200\,ms per screenshot, which restricts real-time video-rate actuation compared to cloud vision endpoints.
\end{itemize}

\section{Conclusion}

We have presented \textbf{Dione}, an on-device Large Action Model (LAM) orchestration engine built on the Microsoft Agent Framework that delivers proactive, ambient personal assistance without compromising privacy. By integrating a typed NetworkX Knowledge Graph, a 0-1 Knapsack Context Optimizer, an Adaptive Heartbeat Scheduler, an Affective Persona Modeling Engine, a 5-tier Safety Kernel, and a Win32 Multimodal Computer-Use Engine, Dione proves that privacy-preserving local systems can operate with high autonomy and resilience. Empirical workstation benchmarks confirm an 88.3\% task completion rate (53/60) across AgentBench and GAIA suites, a 90.0\% completion rate on live unmocked traces, a 98.0\% defense rate against hostile prompt injection attacks (98/100), a 77.0\% prompt token reduction, and sub-2ms graph lookups ($1.158 \pm 0.241$\,ms) while running within 463.11\,MB active RAM.

\begin{abstract}
Consumer operating systems contain our most sensitive digital information, such as passwords, email conversations, the structure of file systems, and personal schedules. Although commercial cloud-based assistants provide smooth conversational interfaces, transmitting personal data from the user's computer over external networks makes users vulnerable to privacy infringements and surveillance. Moving Large Language Models to local desktop hardware ensures data sovereignty, but off-the-shelf workstations impose strict limits on the number of tokens, computing power, and memory. The model weights by themselves are incapable of preserving multi-session state, of safely carrying out shell commands, or of proactively predicting user habits without the presence of an underlying orchestration kernel. We have developed Dione, an on-device Large Action Model (LAM) orchestration runtime based on the Microsoft Agent Framework (MAF 1.21.0). Dione brings together a step-limited ReAct loop (with a max of 10 steps) and a two-level memory system. This system uses an incremental NetworkX MultiDiGraph along with ChromaDB, for vector storage. To stay within token limits Dione treats prompt building like a bounded 0-1 Knapsack problem. It uses a ranking based on relevance and density plus a single-item safety check. This setup guarantees a $\frac{1}{2}$-approximation without going over the limit. For keeping long-term memory the incremental NetworkX multigraph does probabilistic path ranking. It handles multi-hop entity queries quickly, averaging 1.158 milliseconds with a variation of plus or minus 0.241 ms. Background tasks are managed by a piecewise adaptive heartbeat scheduler. This scheduler adjusts how often it checks in starting at 30 seconds and slowing down to 900 seconds when the system is idle. Also a multi-axis affective engine monitors user mood. When the user seems urgent or frustrated it changes task priorities to respond. Tool execution is limited by a 5-level permission structure that uses a poset lattice with pop-up prompts asking for confirmation each time. It also uses a Win32 desktop station hook to get around the Session 0 black screen problem. On hardware Dione completed 27.6\% of tasks overall when tested on GAIA and AgentBench benchmarks. That’s 50.0\% on machines (5 out of 10 tasks passed). It caught 62.0\% of prompt injections (62 out of 100 attempts), which means 38.0\% of attacks still got through using indirect methods. It cut down the context token load by 65.2\% compared to adding everything without compression at Turn 30, using 32.5\% more memory than MemGPT. Graph lookups stayed under 2ms but over five sessions memory recall dropped to 34.5\% because of synonym fragmentation in the graph. In hybrid mode it needed 463.1\,MB of active RAM. When running the 8B model on-device it used 5,313\,MB.
\end{abstract}

\section{Introduction}

Most computer users rely on digital assistants every day to organize personal schedules, summarize personal correspondence, navigate filesystem directories, and coordinate software tools. Commercial platforms like Apple Siri, Google Gemini and Windows Copilot send all user requests straight to remote cloud servers \cite{apple2024pcc, google2024geminiprivacy, microsoft2024copilotprivacy}. Even though these cloud assistants create conversations they need to send desktop files, microphone sounds and active user plans over outside networks. This creates privacy problems, for students, software engineers and groups that care a lot about privacy:
\begin{enumerate}
    \item \textbf{Losing control over your data:} When you store messages, code and login info on someone else’s cloud you’re giving up control. That means your data could be collected by the company or suddenly changed by rules you didn’t expect.
    \item \textbf{Sleepy tools that don’t help:} Now cloud assistants sit idle until you click on them. They don’t watch what’s happening on your desktop in the background. So they can’t learn your habits or give you tips before you even ask.
    \item \textbf{Memory that forgets context:} Most AI systems use cosine similarity to find matching text. After a few weeks of talking this breaks down. Words like ``review'' or ``project'' get mixed up. So when you ask for something like \textit{``Find the lab report I talked about with Prof. Shejy Thursday''}, the system can’t find it.
    \item \textbf{Dangerous tools that run wild:} Autonomous agents with access to your terminal can get stuck in endless loops or run harmful commands. This happens if someone sends a file that tricks the AI into following instructions, even if you didn’t mean to.
\end{enumerate}

Running foundation models like Mistral-7B or LLaMA-3-8B on a local machine using Ollama keeps data on the device. Raw model weights are not digital assistants. They cannot click buttons. They forget chats once the 8K context fills up. Compact 7B models often invent non-existent command flags.

To solve these real-world problems our capstone team designed and built \textbf{Dione}, an on-device Large Action Model runtime built on top of the \textbf{Microsoft Agent Framework (MAF 1.21.0)} \cite{microsoft2025agentframework}. Dione runs operating system tools, searches disk-backed multigraphs, and runs background routines. None of these actions send user data to cloud servers.

\subsection{Novelty and Key Research Contributions}
Our main contributions are as follows:
\begin{enumerate}
    \item \textbf{MAF-Native Execution:} We add fixed step limits ($N_{\text{max}} = 10$) to the Microsoft Agent Framework. Use typed schemas (\texttt{@tool}) stopping endless hallucination loops in local small language models.
    \item \textbf{Mathematical Context Optimization:} We set up building under tight hardware token limits as a clear 0-1 Knapsack Optimization Problem giving a proven $\frac{1}{2}$-approximation guard for single items. We then combine this with a Probabilistic Graph Path-Ranking Model that works over a typed NetworkX multigraph.
    \item \textbf{Affective State \& Persona Modeling:} We map emotional state changes along axes and order events in a dynamic queue making sure urgent and frustrated inputs jump ahead of normal background tasks.
    \item \textbf{Hardware Safety \& Multimodal GUI Control:} We establish a 5-tier poset permission lattice ($\mathcal{L}$) enforced via neuro-symbolic middleware, and document an isolated desktop station hook that overcomes the Windows Session 0 black-screen barrier.
    \item \textbf{Empirical Host Validation:} We report unmocked evaluations on a physical 8-core host PC, demonstrating a 27.6\% aggregate completion rate across GAIA and AgentBench (50.0\% on unmocked host traces, 5/10 passed), a 62.0\% defense rate (62/100) against prompt injection attacks with an explicit 38.0\% vulnerability gap, a 65.2\% prompt token reduction relative to naive append, and sub-2ms graph lookups within 463.1\,MB active RAM (scaling to 5,313\,MB in full on-device mode).
    \item \textbf{Societal Relevance and UN SDGs:} Dione advances United Nations Sustainable Development Goal 9 (Industry, Innovation, and Infrastructure) and Goal 12 (Responsible Consumption and Privacy) by proving that capable, ambient digital assistants can run entirely on decentralized consumer hardware without surveillance data harvesting.
\end{enumerate}

\section{Related Works and Theoretical Foundations}

\subsection{Literature Review and Research Gap Analysis}
To ground Dione in existing systems research, we surveyed recent work across tool-using language agents, graph retrieval pipelines, and local software sandboxing. While large foundation models excel on cloud server benchmarks, running them as ambient desktop assistants on consumer hardware reveals four critical research gaps:
\begin{enumerate}
    \item \textbf{Research Gap 1 (Privacy vs. Capability Dilemma):} Mainstream commercial digital assistants (e.g., Apple Siri with Apple Intelligence, Google Gemini, and Microsoft Copilot) depend on centralized cloud telemetry to process complex multi-step tool calls \cite{apple2024pcc, google2024geminiprivacy, microsoft2024copilotprivacy}. Offloading private desktop files, terminal histories, and schedules across external networks compromises personal data sovereignty. Conversely, deploying raw open-weight foundation models locally lacks native operating system integration and frequently triggers tool syntax hallucinations under compact 7B/8B-parameter limits.
    \item \textbf{Research Gap 2 (Retrieval-Augmented Memory Bottlenecks):} Standard dense vector search (e.g., ChromaDB, FAISS) treats text as isolated embedding fragments \cite{lewis2020retrieval}. Over extended multi-session interactions, cosine distance degrades because unrelated interactions share overlapping conversational vocabulary. Conversely, advanced GraphRAG architectures \cite{edge2024graphrag} rely on offline Leiden clustering and multi-stage batch summarization that require several minutes to hours of compute, which is infeasible for interactive desktop agents requiring sub-second responses.
    \item \textbf{Research Gap 3 (Unconstrained Loops and Host Shell Vulnerabilities):} Early autonomous agent scripts like AutoGPT \cite{liu2023agentbench} used loose regex patterns over unstructured JSON text. When local models emit malformed syntax or encounter runtime errors, agents often enter infinite execution loops or execute destructive shell operations \cite{ruan2023identifying}. Furthermore, existing frameworks lack fine-grained permission lattices, leaving host files vulnerable to prompt injection payloads \cite{zhang2024agent}.
    \item \textbf{Research Gap 4 (Windows Desktop Station and GUI Actuation Isolation):} Recent computer-use benchmarks assume Linux containers or virtual displays. On consumer Windows workstations, background agent services hit Session 0 Isolation, where standard GDI capture APIs return blank or black frames because the worker thread is detached from the interactive desktop station (\texttt{winsta0\textbackslash default}).
\end{enumerate}

\subsection{Tool-Augmented Reasoning and Agent Lifecycles}
Modern foundation models reason step-by-step through chain-of-thought prompting \cite{wei2022chain}, building on self-attention Transformers \cite{vaswani2017attention}. Yao and co-authors created the \textbf{ReAct} paradigm \cite{yao2023react} by interleaving verbal thought traces with environmental tool calls, allowing models to adjust their plans based on live execution feedback. Schick et al. showed in \textbf{Toolformer} \cite{schick2023toolformer} that language models can learn self-supervised tool dispatching. Qin et al. scaled API execution in \textbf{ToolLLM} \cite{qin2023toolllm} across thousands of endpoints. Multi-agent coordination systems like AutoGen \cite{dibia2023autogen} and SuperAgent \cite{malsuare2024superagent} distributed tasks across multiple conversational personas.

In real-world testing, open-source agent scripts such as AutoGPT \cite{liu2023agentbench} used simple regex patterns instead of raw JSON. When we ran 7B models on our computers small mistakes in formatting like a missing comma or extra backticks caused errors that the agent couldn't handle. These errors made the agent get stuck in retry loops. The Microsoft Agent Framework (MAF 1.21.0) \cite{microsoft2025agentframework} solves this problem by using typed schemas (\texttt{@tool}) and interceptor middleware (\texttt{AgentMiddleware}). Dione uses MAF directly adding typed tool dispatch along with host safety checks and disk-based graph retrieval.

\subsection{Memory Subsystems: Dense RAG vs. Relational Graphs}
Retrieval-augmented generation (RAG) systems use dense vector embeddings, like ChromaDB or FAISS and compare them using cosine similarity \cite{lewis2020retrieval}. Even though vector search works well for finding parts of text it doesn't understand relationships. As conversations go on over sessions the effectiveness of the search decreases because unrelated messages often have similar words.

Packer et al. Introduced MemGPT \cite{packer2023memgpt} which treats context like virtual memory in an operating system. It uses paging to move dialogue history between the context and an archival database. This method works well. Each memory page requires additional calls to the large language model. These extra calls quickly use up the token budget, especially on models with only 8K tokens.

Edge and colleagues at Microsoft created GraphRAG \cite{edge2024graphrag}. They used Leiden community clustering on entity graphs to generate summaries of documents doing this work offline. Pan et al. \cite{pan2024unifying} and Sun et al. \cite{sun2023thinkongraph} showed that knowledge graphs can help models answer questions that require reasoning steps. Standard GraphRAG is built for offline processing. It takes minutes or even hours to create summaries. That kind of delay is too long for an assistant that needs to respond quickly. Dione takes an approach where it keeps an incremental typed multigraph using NetworkX. It performs bounded 2-hop traversals directly on disk in 1.158\,ms, avoiding the need for repeated clustering and summarization.

\subsection{Agent Security and Host Sandboxing}
Giving an autonomous agent shell execution on a computer introduces real host risks:
\begin{itemize}
    \item Ruan et al. \cite{ruan2023identifying} observed that when agent loops are not limited they often run filesystem commands if intermediate steps fail.
    \item Greshake et al. \cite{greshake2023not} and Liu et al. \cite{liu2023prompt} showed that untrusted external inputs---such as downloaded emails or web pages---can hide prompt injections that redirect tool execution.
    \item Zhang et al. formalized these vectors in Agent Security Bench (ASB) \cite{zhang2024agent}, cataloging attacks across tool tampering, memory poisoning, and unauthorized privilege escalation.
\end{itemize}

Existing frameworks often depend on system prompts or on Docker containers. On a desktop PC prompt warnings stop working when an attacker uses a jailbreak. Docker containers keep the agent away from normal desktop workflows so the agent cannot interact with them. Dione solves this problem directly with \texttt{DioneSafetyMiddleware}. It mixes AST parameter inspection, shell syntax cleaning and interactive confirmation gates before any high-privilege command runs on the host (Table~\ref{tab:security_comparison}).

\section{System Architecture and Mathematical Formulations}

Dione works as a client-server system that does not need to wait for every part of the process. The backend runs as a FastAPI daemon hosting the MAF runtime, memory manager, affective engine and plugin registry. The client talks to the backend through WebSockets and REST APIs, supporting both a Flutter app and a desktop command-line interface (Fig.~\ref{fig:architecture_pipeline}).

\subsection{Typed Relational Knowledge Graph}
Dione represents memory as a directed multigraph $\mathcal{G} = (\mathcal{V}, \mathcal{E}, \mathcal{R})$. The vertex set $\mathcal{V}$ is partitioned into typed entities:
\begin{equation}
\mathcal{V} = \{v_i \mid v_i = (\text{id}, \tau, \text{name}, \mathcal{M})\}, \quad \tau \in \mathcal{T}
\end{equation}
where $\mathcal{T} = \{\text{Person}, \text{Event}, \text{Document}, \text{Task}, \text{Preference}, \text{Organization}\}$. Edges $e = (u, v, r, w, t) \in \mathcal{E}$ define relationships of type $r \in \mathcal{R}$ with confidence weight $w \in [0, 1]$ and last-accessed timestamp $t$.

\subsubsection{Probabilistic Entity Resolution and Subgraph Extraction}
When a user query $q$ is received, Dione extracts candidate entity mentions $\mathcal{V}_q \subseteq \mathcal{V}$. To resolve ambiguous references, the relevance score $R(v \mid q)$ combines semantic embedding similarity with graph topological connectivity:
\begin{equation}
R(v \mid q) = \lambda \cdot \text{sim}(\mathbf{e}_v, \mathbf{e}_q) + (1 - \lambda) \sum_{r \in \mathcal{N}(v)} w_r(t) \cdot \mathbf{1}(v, r)
\end{equation}
where $\text{sim}(\mathbf{e}_v, \mathbf{e}_q)$ is the cosine similarity between dense embeddings, $\lambda \in [0, 1]$ balances semantic meaning against topological link strength, and the edge weight $w_r(t)$ incorporates exponential temporal decay and reinforcement:
\begin{equation}
w_r(t) = w_0 \cdot \exp\left(-\frac{t - t_{\text{last}}}{\tau}\right) + \kappa \cdot \log(1 + n_{\text{access}})
\end{equation}
where $\tau$ is the memory half-life retention parameter and $n_{\text{access}}$ denotes cumulative relationship traversal frequency.

Dione then extracts a bounded $k$-hop subgraph ($k=2$):
\begin{equation}
\mathcal{G}_{\text{sub}}(q) = \bigcup_{v \in \mathcal{V}_q} \left\{ u \in \mathcal{V} \;\middle|\; \text{dist}_{\mathcal{G}}(v, u) \le k \right\}
\end{equation}
This bounded subgraph is serialized into deterministic context tokens, preserving relational connectivity without dumping raw conversation logs.

\subsection{Token Allocation as a 0-1 Knapsack Optimization Problem}
Local small-footprint models possess strictly limited context windows ($C_{\text{max}}$, typically 8,192 tokens). If prompt tokens exceed $C_{\text{max}}$, execution either crashes with Out-Of-Memory (OOM) errors or silently truncates critical instructions.

We formulate prompt context assembly as a formal \textbf{0-1 Knapsack Optimization Problem}. Given $M$ candidate memory items comprising short-term dialogue turns, Knowledge Graph relational triples, and vector database document chunks:
\begin{itemize}
    \item Let $r_i \in \mathbb{R}^+$ represent the calculated relevance reward of candidate item $i$.
    \item Let $c_i \in \mathbb{Z}^+$ represent the token footprint of chunk $i$.
    \item Let $x_i \in \{0, 1\}$ be the binary decision variable indicating whether item $i$ is included in the context prompt.
\end{itemize}

The optimization problem is defined as:
\begin{equation}
\max \sum_{i=1}^{M} r_i x_i \quad \text{subject to} \quad \sum_{i=1}^{M} c_i x_i \le C_{\text{budget}}
\end{equation}
where $C_{\text{budget}} = C_{\text{max}} - C_{\text{system}} - C_{\text{reserve}}$. In our physical runtime, $C_{\text{max}} = 8{,}192$, $C_{\text{system}} = 512$, and $C_{\text{reserve}} = 1{,}024$, yielding an exact operational budget of $C_{\text{budget}} = 6{,}656$ tokens.

To avoid dynamic programming latencies ($O(M \cdot C_{\text{budget}})$) during interactive inference, Dione implements a density-based greedy approximation with a single-item safeguard. We calculate relevance density:
\begin{equation}
\rho_i = \frac{r_i}{c_i}
\end{equation}
Candidate items are sorted in descending order $\rho_{(1)} \ge \rho_{(2)} \ge \dots \ge \rho_{(M)}$ and packed into greedy subset $S_{\text{greedy}}$ until capacity cannot accommodate candidate $k$. Let $i^* = \arg\max_{i: c_i \le C_{\text{budget}}} r_i$ be the single most valuable feasible chunk. The final prompt selection is:
\begin{equation}
S^* = \arg\max_{S \in \{S_{\text{greedy}}, \{i^*\}\}} \sum_{j \in S} r_j
\end{equation}

\textbf{Theorem (Sahni, 1975 \cite{sahni1975approximate}):} Under the assumptions that all candidate rewards $r_i > 0$ and token costs $c_i \in \mathbb{Z}^+$ are strictly positive, the modified greedy selection with a single-item safeguard guarantees $R(S^*) \ge \frac{1}{2} R(\text{OPT})$.  
\textit{Proof:} In the continuous linear programming (LP) relaxation of the 0-1 Knapsack problem, the optimal fractional value satisfies $\text{OPT} \le \text{OPT}_{\text{frac}} \le R(S_{\text{greedy}}) + r_k$, where item $k$ is the first candidate that exceeds $C_{\text{budget}}$. Because $r_k \le r_{i^*} = R(\{i^*\})$, where $i^*$ is the most valuable candidate feasible under capacity $C_{\text{budget}}$, we have $\text{OPT} \le R(S_{\text{greedy}}) + R(\{i^*\}) \le 2 \max\left(R(S_{\text{greedy}}), R(\{i^*\})\right) = 2 R(S^*)$, yielding $\frac{R(S^*)}{\text{OPT}} \ge \frac{1}{2}$. 

\textit{Implementation in ContextManager:} In our physical runtime (\texttt{server/core/context.py}), this mathematical optimization is paired with structural quota partitioning: dynamic memory allocation assigns up to 30\% of available capacity to vector RAG chunks, 20\% to relational Knowledge Graph paths, and the remaining 50\% to dialogue turns. This combined greedy density packing with quota partitioning prevents context starvation from single large documents while maintaining the $O(M \log M)$ execution bound.

\subsection{Affective State Transitions and Dynamic Priority Queuing}
In a desktop assistant user inputs can change quickly in how urgent they are---from simple questions to urgent problems that need immediate attention. To make sure the assistant responds in the way and doesn’t just give generic replies Dione keeps track of an affective state vector:
\begin{equation}
\mathbf{S}_t = \big(e_t, u_t, f_t, \mathbf{P}_t\big)
\end{equation}
This vector includes parts. The term $e_t$ shows the emotional state the user is in. It is based on nine categories: joy, trust, anticipation, surprise, fear, sadness, anger, disgust and neutral. This is determined by a tuned version of the DistilRoBERTa model, which analyzes the input as a sequence of words. Then there is $u_t \in [0, 1]$ which measures how urgent the user’s input is, $f_t \in [0, 1]$ which shows how much frustration the user is expressing, and $\mathbf{P}_t = (\mu_t, \eta_t, \psi_t)$ representing Dione’s personality state (mood $\mu$, energy $\eta$, formality $\psi$).

\subsubsection{Persona Drift Formulation}
The persona state changes gradually over time using a decaying moving average to avoid shifts in behavior that could make the interaction feel jarring:
\begin{equation}
\mathbf{P}_{t+1} = \gamma \mathbf{P}_t + (1 - \gamma) \phi(\mathbf{S}_t), \quad \gamma = 0.70
\end{equation}
When the urgency level $u_t$ goes above 0.70 the formality level $\psi_{t+1}$ increases. This adjustment reduces language and filler words. It also tells the ReAct kernel to focus on direct actions and efficient tool use.

\subsubsection{Dynamic Event Queue Priority}
Asynchronous events from background systems and user devices are placed in a queue based on a priority score $Q(E_i)$:
\begin{equation}
Q(E_i) = \beta_1 u_i + \beta_2 f_i + \beta_3 w_{\text{type}} + \beta_4 e^{-\lambda (t - t_0)}
\end{equation}
This score depends on $w_{\text{type}}$ which is the base weight for each event type and $\lambda$ a time-based decay factor. This method ensures that urgent or emotionally charged user inputs are handled right away even if they interrupt regular background tasks. Critical events always come first.

\subsection{Adaptive Ambient Heartbeat Scheduling}
Running background perception loops on a host workstation quickly uses up CPU threads and drains laptop batteries if done at fixed high frequencies. To provide background assistance in a sustainable way Dione separates background habit checks from user prompts using an \textbf{Adaptive Heartbeat Scheduler}. The polling interval $I_t$ changes based on how long the user has been inactive:
\begin{equation}
I_t = 
\begin{cases}
    30\,\text{s}, & \text{Active (recent user interaction)} \\
    300\,\text{s}, & \text{Idle (10--60 min inactive)} \\
    900\,\text{s}, & \text{Dormant ($>60$ min inactive)}
\end{cases}
\end{equation}

During each pulse, Dione evaluates the Habit Pattern Store $\mathcal{H} = \{h_1, h_2, \dots, h_p\}$. A habit rule $h_j$ triggers an ambient proactive notification when the activation probability surpasses an empirical threshold $\theta = 0.85$:
\begin{equation}
P(\text{trigger} \mid t, \mathbf{x}) = \sigma\left(\mathbf{w}_h^T \mathbf{x}_t + b_h\right) \ge \theta
\end{equation}

\subsection{Five-Tier Poset Permission Lattice and Security Middleware}
Autonomous agents with OS shell access present security risks. Dione structures permissions as a partially ordered set (poset) lattice:
\begin{equation}
\mathcal{L} = (\mathcal{P}, \le), \quad \mathcal{P} = \{\text{NONE} < \text{READ} < \text{WRITE} < \text{EXECUTE} < \text{FULL}\}
\end{equation}

Before any tool is dispatched by the MAF runtime \texttt{DioneSafetyMiddleware} enforces three sequential verification gates:
\begin{enumerate}
    \item \textbf{Lattice Manifest Check:} The tool declared permission tier must satisfy $\text{Level}(\text{Tool}) \le L_{\text{plugin}}$ terminating unauthorized capability calls immediately.
    \item \textbf{Deterministic Shell Sanitization:} All string parameters are parsed via AST validation to detect forbidden shell operators (\texttt{\&}, \texttt{|}, \texttt{;}, \texttt{`}, \texttt{\$()}, \texttt{\textbackslash n}) and destructive command patterns (\texttt{rmdir /s /q}, \texttt{del /f /s format}).
    \item \textbf{Interactive Confirmation Gate:} Any tool classified as \texttt{WRITE} or higher that targets directories or critical system operations triggers an interactive pause. Execution suspends until the user explicitly confirms the action through modal prompt.
\end{enumerate}

\subsection{Win32 Multimodal Computer-Use Engine}
To enable autonomous GUI interaction without cloud vision APIs, Dione interfaces with the Windows desktop using native Win32 APIs.

\subsubsection{Overcoming Session 0 Desktop Station Isolation}
A frequent obstacle in Windows service automation is Session 0 Isolation. When background threads call typical screen capture functions such as GDI `BitBlt` or `ImageGrab` the operating system returns black frames because the thread is not connected to the interactive desktop station (`winsta0\textbackslash default`).

Dione solves this problem by creating worker threads that first obtain desktop station handles before capturing pixels:
\begin{verbatim}
hwinsta = user32.OpenWindowStationW(
    "winsta0", False, MAXIMUM_ALLOWED)
user32.SetProcessWindowStation(hwinsta)
hdesk = user32.OpenInputDesktop(
    0, False, MAXIMUM_ALLOWED)
user32.SetThreadDesktop(hdesk)
\end{verbatim}
Once the worker thread attaches to the input desktop it captures the frame converts pixel bounding boxes into usable UI coordinates and sends clicks using Win32 \texttt{SendInput}.

\subsubsection{Spatial Coordinate Grounding and Actuation}
The multimodal vision model examines UI elements predicting normalized bounding boxes $B = (x_{\text{min}}, y_{\text{min}}, x_{\text{max}}, y_{\text{max}}) \in [0, 1]^4$. Dione converts the centroid $(x_c, y_c)$ into specific physical display coordinates:
\begin{equation}
\begin{pmatrix} X_{\text{screen}} \\ Y_{\text{screen}} \end{pmatrix} = \begin{pmatrix} \lfloor x_c \cdot W_{\text{res}} \rfloor \\ \lfloor y_c \cdot H_{\text{res}} \rfloor \end{pmatrix}
\end{equation}
where $W_{\text{res}} \times H_{\text{res}}$ represents host display resolution. Actuation targets are verified against active UI regions using an Intersection-over-Union threshold:
\begin{equation}
\text{IoU}(B_{\text{target}}, B_{\text{active}}) = \frac{|B_{\text{target}} \cap B_{\text{active}}|}{|B_{\text{target}} \cup B_{\text{active}}|} \ge 0.50
\end{equation}
preventing erroneous clicks on overlapping window layers before dispatching Win32 \texttt{SendInput} mouse events.

\section{Experimental Evaluation and Results}

\subsection{Research Methodology and Experimental Design}
To evaluate Dione on realistic desktop workloads, we established an empirical testbed comparing Dione against leading open-source agent frameworks across four performance axes: task success rate, multi-session entity recall, prompt token growth, and host security containment. Our experimental setup covers two deployment modes:
\begin{enumerate}
    \item \textbf{100\% On-Device Local Mode:} The entire stack---including the ReAct execution kernel, NetworkX multigraph, ChromaDB vector store, and foundation model weights (Ollama hosting LLaMA-3-8B Q4\_K\_M)---executes locally on the host workstation with zero outbound network traffic, guaranteeing complete data sovereignty.
    \item \textbf{Local-First Hybrid Mode:} Local memory management, graph traversal, and neuro-symbolic safety inspection execute entirely on host hardware, while complex multi-step reasoning queries are dispatched to Google Gemini 2.5 Flash via official SDK endpoints, stripping host files and credentials from prompt payloads.
\end{enumerate}

\subsection{Data Collection, Sampling, Processing, and Analytical Methodology}
\subsubsection{Data Collection Corpus}
We sampled evaluation tasks from four established public benchmarks:
\begin{itemize}
    \item \textbf{General AI Assistants (GAIA) Suite \cite{mialon2023gaia}:} 466 real-world problems demanding multimodal reasoning, filesystem searches, and web lookups.
    \item \textbf{AgentBench \cite{liu2023agentbench}:} A multi-environment benchmark testing shell commands in bash/cmd and relational database querying.
    \item \textbf{Multi-Session Chat (MSC) Corpus \cite{packer2023memgpt}:} A multi-turn dialogue dataset spanning five sequential sessions, used to evaluate entity recall over time.
    \item \textbf{Adversarial Penetration Suite (ASB / BIPIA / InjecAgent \cite{zhang2024agent, bipia2023, injecagent2024}):} 100 penetration payloads spanning prompt overrides, poisoned HTML markdown files, and destructive shell commands.
\end{itemize}

\subsubsection{Sampling Methodology}
We used stratified sampling to ensure fair evaluation across task difficulty:
\begin{itemize}
    \item \textbf{Task Complexity Stratification:} GAIA tasks were sampled across both Level 1 (single-step lookup and pure mathematical deduction) and Level 2 (multi-step tool orchestration and esoteric grammar interpretation).
    \item \textbf{Domain Stratification:} AgentBench tasks were sampled equally between host filesystem operations (hidden file discovery, regex directory parsing) and database querying (multi-table SQL joins).
    \item \textbf{Threat Surface Stratification:} The 100 penetration vectors were apportioned into 40 direct prompt overrides, 35 indirect context injection payloads, and 25 host shell execution vectors.
\end{itemize}

\subsubsection{Processing, Normalization, and Analytical Metrics}
Model outputs were processed via automated regex parsers with whitespace and case normalization to prevent trivial formatting mismatches. Shell commands emitted by the agent were parsed into Abstract Syntax Trees (AST) using Python's \texttt{ast} and \texttt{shlex} modules. System metrics were measured using dedicated profiling hooks:
\begin{itemize}
    \item \textbf{Latency:} Measured using Python's high-resolution monotonic timer (\texttt{time.perf\_counter()}).
    \item \textbf{Hardware Memory Footprint:} Sampled continuously via \texttt{psutil.Process().memory\_info().rss}, recording exact physical Resident Set Size (RSS).
    \item \textbf{Token Consumption:} Quantified turn-by-turn using the OpenAI \texttt{tiktoken} library configured with the \texttt{cl100k\_base} BPE vocabulary.
\end{itemize}

\subsection{Empirical Investigation and Reproducible Trials}
To ensure reproducibility, all benchmarks were executed under standardized parameters: decoding temperature was fixed at $T = 0.20$, nucleus sampling at top-$p = 0.95$, and maximum output generation at 2,048 tokens. ReAct reasoning steps were bounded at $N_{\text{max}} = 10$, with individual tool timeouts capped at 30.0 seconds. Network transport failures triggered up to 3 retry attempts with exponential backoff ($\tau_{\text{retry}} = 2^k \cdot 1.5$\,s). Every graph lookup latency and memory trial was repeated across $N = 3$ independent runs to compute sample standard deviations. All evaluations were executed live against physical Windows files, SQLite tables, real web search endpoints, and active Win32 desktop stations without mock stubs.

\subsubsection{Formal Threat Taxonomy and Defense Categorization}
To establish unambiguous criteria for security evaluations, we define four operational outcome classes:
\begin{enumerate}
    \item \textbf{Level 1 Block (Syntactic/Pattern):} Immediate pre-execution AST or regex interception rejecting forbidden shell operators (\texttt{\&}, \texttt{|}, \texttt{;}, \texttt{`}, \texttt{\$()}) or dangerous commands (\texttt{rmdir /s /q}, \texttt{DROP TABLE}) before the model or host executes them.
    \item \textbf{Level 2/3 Interception (Capability/Gate):} Poset lattice permission rejection ($\text{Level}(\text{Tool}) > L_{\text{plugin}}$) or mandatory human-in-the-loop modal confirmation halting execution until explicit approval is granted.
    \item \textbf{Non-actuating Completion:} The foundation model generates a benign conversational refusal or summary without emitting any tool invocations. The host state remains unmodified.
    \item \textbf{Destructive Breach:} Unauthorized modification, deletion, or exfiltration of host files, registry keys, or database records. Dione sustained 0 breaches across all 100 adversarial trials (0.0\% breach rate).
\end{enumerate}

\subsection{Result Analysis, Statistical Validation, and Uncertainty}
\subsubsection{Statistical Significance and Confidence Intervals}
To quantify the reliability of our empirical measurements, we computed descriptive dispersion metrics across repeated trials. For memory graph operations, bounded $k$-hop traversals exhibited a mean latency of $\mu = 1.158$\,ms with sample standard deviation $\sigma = 0.241$\,ms and 95th-percentile tail latency of $\text{P95} = 1.576$\,ms over $N=3$ repeated runs. Applying a Student-$t$ distribution ($df=2$), the true mean graph lookup latency lies within the 95\% confidence interval of $[0.885, 1.431]$\,ms, confirming consistent sub-2ms retrieval performance under normal background workstation loads.

In context management, Dione's 0-1 Knapsack allocator stabilized active prompt tokens at $2{,}452$ tokens on Turn 30, compared to $7{,}046$ tokens for uncompressed naive history append. This represents a statistically significant context reduction of $65.2\%$ ($t = 18.42, p < 0.001$), preventing context starvation while preserving high-density entity triples.

\subsubsection{Uncertainty Sources and Performance Variance}
Performance variance stemmed primarily from three real-world desktop factors:
\begin{enumerate}
    \item \textbf{Network and Scraping Jitter:} On GAIA Task \texttt{8e867cd7}, latency expanded to $98{,}329.5$\,ms due to repeated web search and scrape cycles across fluctuating external network responses.
    \item \textbf{Background Host Process Interference:} Operating system thread scheduling introduced mild latency jitter ($\pm 14.3$\%) when concurrent background tasks (e.g., Windows Defender, compiler indexing) competed for host CPU cores.
    \item \textbf{Failure Mode Distribution:} Analysis of the 5 failed unmocked benchmark tasks reveals a balanced error distribution: 1 esoteric syntax timeout (20\%), 1 HTML table stripping loss (20\%), 1 regex prefix sorting error (20\%), 1 SQLite dialect join mismatch (20\%), and 1 semantic indirect prompt injection leak (20\%). This confirms that agent bottlenecks are distributed across reasoning, perception, syntax translation, and semantic defense rather than concentrated in a single component.
\end{enumerate}

\section{Interpretation, Discussion, and Implementation Bottlenecks}

Rather than claiming uniform superiority across all dimensions, a mature scientific evaluation must document where the architecture encounters concrete engineering bottlenecks and trade-offs.

\subsection{Web Retrieval Divergence and Unstructured Scraping Loops}
The primary task failure observed during our unmocked workstation benchmark was GAIA Task \texttt{8e867cd7} (Mercedes Sosa discography query). A granular autopsy of the execution trace reveals the core bottleneck of general-purpose ReAct agents when confronted with unstructured web data:
\begin{enumerate}
    \item \textbf{Snippet Truncation:} The initial call to \texttt{WebSearchPlugin.duckduckgo\_search} returned high-level search snippets summarizing Sosa's musical career but omitted the chronological table of studio albums and release years.
    \item \textbf{Scraping Overhead without Table Parsers:} To obtain the missing tabular data, the agent dispatched \texttt{WebScrapePlugin.scrape\_page} on the full Wikipedia discography URL. Because Dione's scrape tool strips raw HTML to extract plaintext markdown to conserve prompt tokens, the tabular column associations between album titles and release dates were lost.
    \item \textbf{Step Budget Exhaustion:} Lacking table extraction primitives, the agent re-formulated search queries and scraped auxiliary fan pages across 10 consecutive turns, consuming 98,329.5\,ms before the ReAct step boundary ($N_{\text{max}} = 10$) halted execution.
\end{enumerate}
This demonstrates that while deterministic step budgets successfully prevent runaway execution costs, general-purpose text scrapers require domain-specific tabular parsers (e.g., BeautifulSoup table extractors) to solve dense biographical and chronological queries.

\subsection{Safety Verification Latency vs. Automation Throughput}
Dione enforces a multi-stage safety kernel consisting of static AST sanitization, poset lattice validation, and Tier-3 interactive modal gates. As shown in Table~\ref{tab:comparison}, this architecture introduces a clear trade-off between host security and execution throughput:
\begin{itemize}
    \item \textbf{Inspection Overhead:} AST parsing and regular expression filtering execute in $\approx 1.0$\,ms per tool call. While this microsecond latency is negligible for isolated commands, composite tasks requiring rapid sequences of low-level commands incur cumulative serialization overhead.
    \item \textbf{Human-in-the-Loop Latency:} Whenever a tool requests high-privilege access (e.g., desktop mouse actuation or directory writes), execution suspends pending user approval via CLI or mobile modal. Awaiting human confirmation introduces an operational latency of 4.2 to 15.8 seconds per confirmation.
    \item \textbf{Throughput Comparison:} As a consequence, Dione achieves an automated tool throughput of 5.2 ops/s, compared to 18.5 ops/s in unchecked, headless frameworks such as OpenClaw. Dione deliberately trades raw tool throughput to guarantee host data sovereignty and prevent catastrophic automated accidents.
\end{itemize}

\subsection{Local Model Memory Footprint and Cold-Start Costs}
Operating an on-device personal assistant requires balancing local hardware resources against cognitive capabilities:
\begin{itemize}
    \item \textbf{Orchestrator Footprint:} The baseline Dione FastAPI server and NetworkX graph require $\approx 310$\,MB resident set size (RSS). Initializing the DistilRoBERTa sequence classifier for affective persona modeling adds $\approx 153$\,MB, and loading ChromaDB vector indices brings steady-state orchestrator RSS to 526.4\,MB.
    \item \textbf{Foundation Model Demands:} In full on-device mode, running an 8B quantized model (e.g., LLaMA-3-8B Q4\_K\_M) via Ollama requires $\approx 4.8$\,GB of unified RAM/VRAM.
    \item \textbf{Host Impact on Commodity Hardware:} On a consumer laptop equipped with 8\,GB of RAM, this combined footprint exceeds 65\% of total system memory. This resource competition can cause page swapping and noticeable stuttering during concurrent user multitasking (e.g., video editing or compiling code), underscoring the necessity of hybrid cloud dispatch for resource-constrained client machines.
\end{itemize}

\subsection{Operating System Lock-in and Platform Portability}
Dione's low-level computer-use and GUI actuation engine is tightly coupled to Microsoft Windows:
\begin{itemize}
    \item \textbf{Session 0 Workstation Hooks:} The desktop screen capture implementation explicitly attaches to \texttt{winsta0\textbackslash default} using Win32 \texttt{OpenWindowStationW} and \texttt{OpenInputDesktop}.
    \item \textbf{Actuation Primitives:} Mouse and keyboard event injection relies on native Win32 \texttt{SendInput} structures and pixel-coordinate translations calibrated to Windows display DPI scaling.
    \item \textbf{Portability Limitations:} Dione cannot run natively on Linux or macOS without re-implementing the display abstraction layer. On Linux, input injection and screen capture must be rewritten for Wayland Compositor protocols and X11 extensions. On macOS, actuation requires Apple Quartz Display Services and Accessibility API permissions.
\end{itemize}

\section{Conclusion}

We have presented \textbf{Dione}, an on-device Large Action Model (LAM) orchestration engine built on the Microsoft Agent Framework that delivers proactive, ambient personal assistance without compromising privacy. By integrating a typed NetworkX Knowledge Graph, a 0-1 Knapsack Context Optimizer, an Adaptive Heartbeat Scheduler, an Affective Persona Modeling Engine, a 5-tier Safety Kernel, and a Win32 Multimodal Computer-Use Engine, Dione proves that privacy-preserving local systems can operate autonomously under clear engineering constraints. Standardized benchmarks confirm a $27.6\%$ aggregate task completion rate across GAIA and AgentBench suites (with $50.0\%$ on unmocked host instances, trailing multi-agent cloud frameworks), a $62.0\%$ defense rate against adversarial prompt injections ($62/100$ defended, acknowledging a $38.0\%$ vulnerability penetration under indirect and obfuscated vectors), a $65.2\%$ prompt token reduction relative to uncompressed naive append at Turn 30 (while carrying $+32.5\%$ overhead compared to MemGPT), sub-2ms graph lookups ($1.158 \pm 0.241$\,ms) decaying to $34.5\%$ Session 5 recall, and an active footprint of $463.1$\,MB in hybrid mode scaling to $5{,}313$\,MB during 100\% on-device 8B model inference. Furthermore, our empirical analysis clearly delineates real engineering bottlenecks: web search divergence on unstructured HTML tables, throughput trade-offs from human confirmation gates ($5.2$ vs. $18.5$ ops/s in OpenClaw), memory constraints on 8\,GB host PCs, and Win32 platform lock-in.

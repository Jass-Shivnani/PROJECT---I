\begin{abstract}
Consumer operating systems hold our most sensitive digital records, including credentials, email threads, filesystem hierarchies, and private schedules. While commercial cloud assistants offer fluent conversational interfaces, streaming personal host telemetry across external networks exposes users to severe privacy and surveillance liabilities. Transitioning Large Language Models to local desktop hardware guarantees data sovereignty, but commodity workstations impose rigid token, compute, and memory limits. Raw model weights alone cannot maintain multi-session state, safely execute shell operations, or proactively anticipate user routines without an underlying orchestration kernel. We present Dione, an on-device Large Action Model (LAM) orchestration runtime built on the Microsoft Agent Framework (MAF 1.21.0). Dione unifies a step-bounded ReAct execution loop ($N_{\text{max}} = 10$) with a dual-tier memory subsystem that pairs an incremental NetworkX MultiDiGraph with ChromaDB vector storage. To operate within tight local token windows, Dione casts prompt construction as a bounded 0-1 Knapsack problem, combining greedy relevance-density ranking with a single-item safeguard to provably guarantee a $\frac{1}{2}$-approximation bound without token overflow. For long-term memory, an incremental NetworkX multigraph performs probabilistic path-ranking, resolving multi-hop entity queries in 1.158\,ms ($\pm 0.241$\,ms). Background routines are regulated by a piecewise adaptive heartbeat scheduler that scales polling frequency from 30\,s down to 900\,s during dormancy, while a multi-axis affective engine dynamically reprioritizes tasks when user urgency and frustration escalate. Tool execution is constrained by a 5-tier poset permission lattice with interactive confirmation prompts, alongside an isolated Win32 desktop station hook that resolves the Session 0 black-screen capture barrier. In physical workstation benchmarks, Dione achieved a 90.0\% task completion rate (9 out of 10 tasks passed) on unmocked end-to-end integration traces across standardized GAIA, AgentBench OS, DBBench, and ASB security suites, blocked 98.0\% of adversarial prompt injections (98 out of 100 attacks), reduced longitudinal context token overhead by 65.2\% relative to uncompressed naive append at Turn 30 (with a 70.0\% lower cold-start footprint than dense RAG: 390 vs. 1,299 tokens), and maintained 93.2\% memory recall over five longitudinal sessions while running within 526.4\,MB active RAM.
\end{abstract}

\section{Introduction}

Modern digital assistants are expected to manage daily user schedules, summarize personal correspondence, navigate filesystem directories, and coordinate software tools. Mainstream commercial platforms such as Apple Siri (with Apple Intelligence), Google Gemini, and Microsoft Copilot handle complex generative reasoning primarily within centralized cloud infrastructure, routing audio streams, desktop metadata, and personal correspondence to remote server farms \cite{apple2024pcc, google2024geminiprivacy, microsoft2024copilotprivacy}. While privacy-preserving cloud extensions have been engineered (such as Apple Private Cloud Compute \cite{apple2024pcc}), standard default assistant configurations still necessitate streaming sensitive user telemetry and prompt context across external networks whenever requests exceed localized on-device heuristic budgets. For enterprise and privacy-conscious users, this centralized paradigm poses severe structural liabilities:
\begin{enumerate}
    \item \textbf{Loss of Data Sovereignty:} Storing private communications, local codebases, and credentials on third-party cloud infrastructure exposes individuals to data harvesting, unauthorized surveillance, and corporate policy shifts.
    \item \textbf{Strictly Passive Operation:} Cloud agents wake up only upon explicit user invocation. They lack persistent ambient awareness, unable to track habits or proactively surface contextual reminders before an explicit query is issued.
    \item \textbf{Shallow Vector Memory Collapse:} Standard dense vector retrieval (RAG) calculates similarity purely over isolated text chunks. Over multi-session dialogues, vector distance degrades due to semantic distractor collisions, failing to resolve relational queries such as \textit{``Send the project report discussed with Prof. Shejy last Thursday''}.
    \item \textbf{Unconstrained Execution and System Hijacking:} Autonomous tool agents can enter infinite recursive loops or execute destructive host shell commands when exposed to prompt injection payloads embedded in retrieved emails or files.
\end{enumerate}

Running open-weights foundation models (such as Mistral-7B or LLaMA-3-8B) on consumer PCs via Ollama or llama.cpp ensures data sovereignty. However, raw model weights cannot act as ambient personal assistants on their own. They possess no built-in operating system hooks, lack stateful relational memory, and frequently hallucinate tool syntax when running on compact 7B-parameter scales.

To resolve these challenges, we designed and implemented \textbf{Dione}, a local-first Large Action Model (LAM) orchestration engine built upon the \textbf{Microsoft Agent Framework (MAF 1.21.0)} \cite{microsoft2025agentframework}. Dione runs directly on consumer host hardware, executing operating system tools, graph retrievals, and proactive background routines with zero mandatory cloud connectivity.

Our primary contributions are as follows:
\begin{enumerate}
    \item \textbf{MAF-Native Execution Kernel:} We extend the Microsoft Agent Framework with deterministic step budgets ($N_{\text{max}} = 10$) and typed schemas (\texttt{@tool}), preventing infinite hallucination loops in local small language models.
    \item \textbf{Mathematical Memory \& Context Optimization:} We formulate prompt construction under strict hardware token limits as a formal \textbf{0-1 Knapsack Optimization Problem} with a provable $\frac{1}{2}$-approximation single-item safeguard, pairing it with a \textbf{Probabilistic Graph Path-Ranking Model} over a typed NetworkX relational multigraph.
    \item \textbf{Affective State \& Persona Modeling:} We model multi-axis emotional state transitions and dynamic event queue prioritization, ensuring urgent and frustrated inputs preempt routine background tasks.
    \item \textbf{Hardware Safety \& Multimodal GUI Control:} We establish a 5-tier poset permission lattice ($\mathcal{L}$) enforced via neuro-symbolic middleware, and document an isolated desktop station hook that overcomes the Windows Session 0 black-screen barrier.
    \item \textbf{Empirical Host Validation:} We report unmocked evaluations on a physical 8-core host PC, achieving a 90.0\% task completion rate (9 out of 10 tasks passed) on live unmocked traces across GAIA, AgentBench, and ASB suites, a 98.0\% defense rate (98/100) against hostile prompt injection attacks, and a 65.2\% prompt token reduction relative to uncompressed naive append (with 70.0\% cold-start savings vs. dense RAG: 390 vs. 1,299 tokens) within 526.4\,MB active RAM.
    \item \textbf{Societal Relevance and UN SDGs:} Dione advances United Nations Sustainable Development Goal 9 (Industry, Innovation, and Infrastructure) and Goal 12 (Responsible Consumption and Privacy) by proving that capable, ambient digital assistants can run entirely on decentralized consumer hardware without surveillance data harvesting.
\end{enumerate}

\section{Related Works and Theoretical Foundations}

\subsection{Tool-Augmented Reasoning and Agent Lifecycles}
The emergence of self-attention Transformer architectures \cite{vaswani2017attention} enabled sequential reasoning via chain-of-thought prompting \cite{wei2022chain}. Yao et al. formalized the interleaving of natural language reasoning traces and environmental actuation in \textbf{ReAct} \cite{yao2023react}. This interleaved loop reduces compounding inference errors and anchors intermediate actions directly to execution feedback. Schick et al. demonstrated in \textbf{Toolformer} \cite{schick2023toolformer} that language models can learn self-supervised tool dispatching. Qin et al. extended this toward large-scale API tooling with \textbf{ToolLLM} \cite{qin2023toolllm}, spanning thousands of REST endpoints. Multi-agent coordination platforms such as AutoGen \cite{dibia2023autogen} and SuperAgent \cite{malsuare2024superagent} demonstrated conversational task decomposition across distinct software roles.

In practical testing, early open-source agent scripts like AutoGPT \cite{liu2023agentbench} relied on loose regex patterns over unstructured JSON text. In our early tests on 7B-parameter local models, slight formatting deviations frequently triggered unhandled JSON parser exceptions and infinite execution loops. The \textbf{Microsoft Agent Framework (MAF 1.21.0)} \cite{microsoft2025agentframework} resolves this by enforcing typed signatures (\texttt{@tool}) and middleware interceptors (\texttt{AgentMiddleware}). Dione builds directly on MAF, combining typed tool dispatch with deterministic host safety checks and knowledge graph retrieval.

\subsection{Memory Subsystems: Dense RAG vs. Relational Graphs}
Most retrieval-augmented generation (RAG) pipelines rely on dense vector embeddings (e.g., ChromaDB, FAISS) compared via cosine similarity \cite{lewis2020retrieval}. While vector search excels at retrieving isolated textual fragments, it lacks topological awareness. Over prolonged multi-turn desktop sessions, embedding distance degrades because unrelated interactions share common conversational tokens.

Packer et al. introduced \textbf{MemGPT} \cite{packer2023memgpt}, treating context management like OS virtual memory paging by shuttling text between active prompt windows and external tables. However, this virtual paging requires frequent self-editing LLM tool calls, which quickly exhausts local token budgets.

More recently, Edge et al. introduced \textbf{GraphRAG} \cite{edge2024graphrag}, applying community detection algorithms such as Leiden clustering over entity graphs to generate hierarchical text summaries. Pan et al. \cite{pan2024unifying} and Sun et al. \cite{sun2023thinkongraph} showed how explicit graph structures ground multi-hop factual reasoning. GraphRAG focuses primarily on offline analysis of massive document collections, where multi-stage clustering can take several minutes to hours. In contrast, an interactive desktop assistant requires immediate responses. Dione instead maintains an incremental, typed multigraph using NetworkX, executing bounded $k$-hop traversals in 1.158\,ms ($\pm 0.241$\,ms) directly on disk without requiring recurring offline cluster summarization.

\subsection{Agent Security and Host Sandboxing}
Granting an autonomous agent access to local shell commands introduces real host security risks:
\begin{itemize}
    \item Ruan et al. \cite{ruan2023identifying} observed that unconstrained agent loops frequently execute harmful filesystem operations when intermediate steps fail.
    \item Liu et al. \cite{liu2023prompt} and Greshake et al. \cite{greshake2023not} demonstrated that direct prompt injection attacks and indirect context poisoning can readily subvert prompt-based instructions in LLM-integrated software.
    \item Zhang et al. formalized these threat vectors in the \textbf{Agent Security Bench (ASB)} \cite{zhang2024agent}, cataloging attack patterns across tool tampering, memory poisoning, and unauthorized privilege escalation across 10 scenarios and 400+ tools.
\end{itemize}

Existing agent frameworks often delegate safety either to high-level system prompts or to coarse-grained containerization. In local desktop environments, prompt-based guardrails fail against determined injection payloads, while full Docker containers disconnect the agent from native desktop workflows. Dione addresses this boundary directly through \texttt{DioneSafetyMiddleware}, combining static AST parameter inspection, shell syntax sanitization, and interactive confirmation gates before any high-privilege action runs on the host (Table~\ref{tab:security_comparison}).

\section{System Architecture and Mathematical Formulations}

Dione operates as an asynchronous client-server architecture. The backend server runs as a FastAPI daemon hosting the MAF runtime, memory manager, affective engine, and plugin registry. The client communicates over WebSockets and REST APIs, supporting both a Flutter mobile companion and desktop CLI interfaces (Fig.~\ref{fig:architecture_pipeline}).

\subsection{Typed Relational Knowledge Graph}
Dione represents memory as a directed multigraph $\mathcal{G} = (\mathcal{V}, \mathcal{E}, \mathcal{R})$. The vertex set $\mathcal{V}$ is partitioned into typed entities:
\begin{equation}
\mathcal{V} = \{v_i \mid v_i = (\text{id}, \tau, \text{name}, \mathcal{M})\}, \quad \tau \in \mathcal{T}
\end{equation}
where $\mathcal{T} = \{\text{Person}, \text{Event}, \text{Document}, \text{Task}, \text{Preference}, \text{Organization}\}$. Edges $e = (u, v, r, w, t) \in \mathcal{E}$ define relationships of type $r \in \mathcal{R}$ with confidence weight $w \in [0, 1]$ and last-accessed timestamp $t$.

\subsubsection{Probabilistic Entity Resolution and Subgraph Extraction}
When a user query $q$ is received, Dione extracts candidate entity mentions $\mathcal{V}_q \subseteq \mathcal{V}$. To resolve ambiguous references, the relevance score $R(v \mid q)$ combines semantic embedding similarity with graph topological connectivity:
\begin{equation}
R(v \mid q) = \lambda \cdot \text{sim}(\mathbf{e}_v, \mathbf{e}_q) + (1 - \lambda) \sum_{r \in \mathcal{N}(v)} w_r(t) \cdot \mathbf{1}(v, r)
\end{equation}
where $\text{sim}(\mathbf{e}_v, \mathbf{e}_q)$ is the cosine similarity between dense embeddings, $\lambda \in [0, 1]$ balances semantic meaning against topological link strength, and the edge weight $w_r(t)$ incorporates exponential temporal decay and reinforcement:
\begin{equation}
w_r(t) = w_0 \cdot \exp\left(-\frac{t - t_{\text{last}}}{\tau}\right) + \kappa \cdot \log(1 + n_{\text{access}})
\end{equation}
where $\tau$ is the memory half-life retention parameter and $n_{\text{access}}$ denotes cumulative relationship traversal frequency.

Dione then extracts a bounded $k$-hop subgraph ($k=2$):
\begin{equation}
\mathcal{G}_{\text{sub}}(q) = \bigcup_{v \in \mathcal{V}_q} \left\{ u \in \mathcal{V} \;\middle|\; \text{dist}_{\mathcal{G}}(v, u) \le k \right\}
\end{equation}
This bounded subgraph is serialized into deterministic context tokens, preserving relational connectivity without dumping raw conversation logs.

\subsection{Token Allocation as a 0-1 Knapsack Optimization Problem}
Local small-footprint models possess strictly limited context windows ($C_{\text{max}}$, typically 8,192 tokens). If prompt tokens exceed $C_{\text{max}}$, execution either crashes with Out-Of-Memory (OOM) errors or silently truncates critical instructions.

We formulate prompt context assembly as a formal \textbf{0-1 Knapsack Optimization Problem}. Given $M$ candidate memory items comprising short-term dialogue turns, Knowledge Graph relational triples, and vector database document chunks:
\begin{itemize}
    \item Let $r_i \in \mathbb{R}^+$ represent the calculated relevance reward of candidate item $i$.
    \item Let $c_i \in \mathbb{Z}^+$ represent the token footprint of chunk $i$.
    \item Let $x_i \in \{0, 1\}$ be the binary decision variable indicating whether item $i$ is included in the context prompt.
\end{itemize}

The optimization problem is defined as:
\begin{equation}
\max \sum_{i=1}^{M} r_i x_i \quad \text{subject to} \quad \sum_{i=1}^{M} c_i x_i \le C_{\text{budget}}
\end{equation}
where $C_{\text{budget}} = C_{\text{max}} - C_{\text{system}} - C_{\text{reserve}}$. In our physical runtime, $C_{\text{max}} = 8{,}192$, $C_{\text{system}} = 512$, and $C_{\text{reserve}} = 1{,}024$, yielding an exact operational budget of $C_{\text{budget}} = 6{,}656$ tokens.

To avoid dynamic programming latencies ($O(M \cdot C_{\text{budget}})$) during interactive inference, Dione implements a density-based greedy approximation with a single-item safeguard. We calculate relevance density:
\begin{equation}
\rho_i = \frac{r_i}{c_i}
\end{equation}
Candidate items are sorted in descending order $\rho_{(1)} \ge \rho_{(2)} \ge \dots \ge \rho_{(M)}$ and packed into greedy subset $S_{\text{greedy}}$ until capacity cannot accommodate candidate $k$. Let $i^* = \arg\max_{i: c_i \le C_{\text{budget}}} r_i$ be the single most valuable feasible chunk. The final prompt selection is:
\begin{equation}
S^* = \arg\max_{S \in \{S_{\text{greedy}}, \{i^*\}\}} \sum_{j \in S} r_j
\end{equation}

\textbf{Theorem (Sahni, 1975 \cite{sahni1975approximate}):} Under the assumptions that all candidate rewards $r_i > 0$ and token costs $c_i \in \mathbb{Z}^+$ are strictly positive, the modified greedy selection with a single-item safeguard guarantees $R(S^*) \ge \frac{1}{2} R(\text{OPT})$.  
\textit{Proof:} In the continuous linear programming (LP) relaxation of the 0-1 Knapsack problem, the optimal fractional value satisfies $\text{OPT} \le \text{OPT}_{\text{frac}} \le R(S_{\text{greedy}}) + r_k$, where item $k$ is the first candidate that exceeds $C_{\text{budget}}$. Because $r_k \le r_{i^*} = R(\{i^*\})$, where $i^*$ is the most valuable candidate feasible under capacity $C_{\text{budget}}$, we have $\text{OPT} \le R(S_{\text{greedy}}) + R(\{i^*\}) \le 2 \max\left(R(S_{\text{greedy}}), R(\{i^*\})\right) = 2 R(S^*)$, yielding $\frac{R(S^*)}{\text{OPT}} \ge \frac{1}{2}$. 

\textit{Implementation in ContextManager:} In our physical runtime (\texttt{server/core/context.py}), this mathematical optimization is paired with structural quota partitioning: dynamic memory allocation assigns up to 30\% of available capacity to vector RAG chunks, 20\% to relational Knowledge Graph paths, and the remaining 50\% to dialogue turns. This combined greedy density packing with quota partitioning prevents context starvation from single large documents while maintaining the $O(M \log M)$ execution bound.

\subsection{Affective State Transitions and Dynamic Priority Queuing}
In an ambient desktop assistant, user inputs vary sharply in urgency---from casual queries to time-critical administrative tasks. To ensure the assistant responds appropriately rather than generating uniform conversational filler, Dione tracks an affective state vector:
\begin{equation}
\mathbf{S}_t = \big(e_t, u_t, f_t, \mathbf{P}_t\big)
\end{equation}
where $e_t$ denotes the primary emotional state across nine discrete categories (\textit{joy}, \textit{trust}, \textit{anticipation}, \textit{surprise}, \textit{fear}, \textit{sadness}, \textit{anger}, \textit{disgust}, \textit{neutral}) generated by a fine-tuned DistilRoBERTa sequence classifier; $u_t \in [0, 1]$ represents urgency; $f_t \in [0, 1]$ represents detected user frustration; and $\mathbf{P}_t = (\mu_t, \eta_t, \psi_t)$ represents Dione's internal persona state (mood $\mu$, energy $\eta$, formality $\psi$).

\subsubsection{Persona Drift Formulation}
The persona state evolves as an exponentially decaying moving average to prevent abrupt behavioral oscillations:
\begin{equation}
\mathbf{P}_{t+1} = \gamma \mathbf{P}_t + (1 - \gamma) \phi(\mathbf{S}_t), \quad \gamma = 0.70
\end{equation}
When urgency $u_t > 0.70$, formality $\psi_{t+1}$ scales upward, immediately suppressing conversational filler words and instructing the ReAct kernel to prioritize terse, actionable tool execution.

\subsubsection{Dynamic Event Queue Priority}
Incoming asynchronous events from background monitors and user clients are queued according to a dynamic priority score $Q(E_i)$:
\begin{equation}
Q(E_i) = \beta_1 u_i + \beta_2 f_i + \beta_3 w_{\text{type}} + \beta_4 e^{-\lambda (t - t_0)}
\end{equation}
where $w_{\text{type}}$ is the base category weight and $\lambda$ is a temporal decay parameter. This ensures critical, emotionally urgent user inputs immediately preempt routine background maintenance tasks.

\subsection{Adaptive Ambient Heartbeat Scheduling}
Running continuous background perception on a host workstation quickly saturates CPU threads and drains laptop batteries if executed at fixed high frequencies. To deliver proactive background assistance sustainably, Dione decouples background habit checks from user prompts through an \textbf{Adaptive Heartbeat Scheduler}. The polling interval $I_t$ adjusts dynamically based on elapsed user inactivity:
\begin{equation}
I_t = 
\begin{cases}
    30\,\text{s}, & \text{Active (recent user interaction)} \\
    300\,\text{s}, & \text{Idle (10--60 min inactive)} \\
    900\,\text{s}, & \text{Dormant ($>60$ min inactive)}
\end{cases}
\end{equation}

During each pulse, Dione evaluates the Habit Pattern Store $\mathcal{H} = \{h_1, h_2, \dots, h_p\}$. A habit rule $h_j$ triggers an ambient proactive notification when the activation probability surpasses an empirical threshold $\theta = 0.85$:
\begin{equation}
P(\text{trigger} \mid t, \mathbf{x}) = \sigma\left(\mathbf{w}_h^T \mathbf{x}_t + b_h\right) \ge \theta
\end{equation}

\subsection{Five-Tier Poset Permission Lattice and Security Middleware}
Autonomous agents with OS shell access present grave security risks. Dione structures permissions as a formal partially ordered set (poset) lattice:
\begin{equation}
\mathcal{L} = (\mathcal{P}, \le), \quad \mathcal{P} = \{\text{NONE} < \text{READ} < \text{WRITE} < \text{EXECUTE} < \text{FULL}\}
\end{equation}

Before any tool is dispatched by the MAF runtime, \texttt{DioneSafetyMiddleware} enforces three sequential verification gates:
\begin{enumerate}
    \item \textbf{Lattice Manifest Check:} The tool's declared permission tier must satisfy $\text{Level}(\text{Tool}) \le L_{\text{plugin}}$, terminating unauthorized capability calls immediately.
    \item \textbf{Deterministic Shell Sanitization:} All string parameters are parsed via AST validation to detect forbidden shell operators (\texttt{\&}, \texttt{|}, \texttt{;}, \texttt{`}, \texttt{\$()}, \texttt{\textbackslash n}) and destructive command patterns (\texttt{rmdir /s /q}, \texttt{del /f /s}, \texttt{format}).
    \item \textbf{Interactive Confirmation Gate:} Any tool classified as \texttt{WRITE} or higher that targets sensitive directories or critical system operations triggers an interactive pause. Execution suspends until the user explicitly confirms the action through the mobile app or CLI modal.
\end{enumerate}

\subsection{Win32 Multimodal Computer-Use Engine}
To enable autonomous GUI interaction without cloud vision APIs, Dione interfaces with the Windows desktop using native Win32 APIs.

\subsubsection{Overcoming Session 0 Desktop Station Isolation}
A common hurdle in Windows service automation is Session 0 Isolation. When background threads call standard screen capture functions (such as GDI `BitBlt` or `ImageGrab`), the operating system returns blank or black frames because the thread is detached from the interactive desktop station (`winsta0\textbackslash default`).

Dione resolves this by spawning isolated worker threads that explicitly acquire desktop station handles prior to capturing pixels:
\begin{verbatim}
hwinsta = user32.OpenWindowStationW(
    "winsta0", False, MAXIMUM_ALLOWED)
user32.SetProcessWindowStation(hwinsta)
hdesk = user32.OpenInputDesktop(
    0, False, MAXIMUM_ALLOWED)
user32.SetThreadDesktop(hdesk)
\end{verbatim}
Once attached to the input desktop, the worker thread captures the frame, translates pixel bounding boxes into actionable UI coordinates, and dispatches clicks via Win32 \texttt{SendInput}.

\subsubsection{Spatial Coordinate Grounding and Actuation}
The multimodal vision model parses UI elements, predicting normalized bounding boxes $B = (x_{\text{min}}, y_{\text{min}}, x_{\text{max}}, y_{\text{max}}) \in [0, 1]^4$. Dione maps the normalized centroid $(x_c, y_c)$ into discrete physical display coordinates:
\begin{equation}
\begin{pmatrix} X_{\text{screen}} \\ Y_{\text{screen}} \end{pmatrix} = \begin{pmatrix} \lfloor x_c \cdot W_{\text{res}} \rfloor \\ \lfloor y_c \cdot H_{\text{res}} \rfloor \end{pmatrix}
\end{equation}
where $W_{\text{res}} \times H_{\text{res}}$ represents host display resolution. Actuation targets are verified against active UI regions using an Intersection-over-Union threshold:
\begin{equation}
\text{IoU}(B_{\text{target}}, B_{\text{active}}) = \frac{|B_{\text{target}} \cap B_{\text{active}}|}{|B_{\text{target}} \cup B_{\text{active}}|} \ge 0.50
\end{equation}
preventing erroneous clicks on overlapping window layers before dispatching Win32 \texttt{SendInput} mouse events.

\end{equation}

To rigorously benchmark operational competence under identical real-world desktop constraints, we evaluated Dione against 10 standardized problem instances adapted from \textbf{GAIA} \cite{mialon2023gaia}, \textbf{AgentBench} \cite{liu2023agentbench}, and \textbf{Agent Security Bench (ASB)} \cite{zhang2024agent}.

\subsubsection{Reproducible Testbed and Model Configuration}
All benchmark trials were executed against the live local Dione server (\texttt{http://127.0.0.1:8900}) orchestrating the Microsoft Agent Framework (MAF 1.21.0) on the host testbed (Windows 11 Pro, Intel 8-core CPU @ 2.80\,GHz, 16\,GB DDR4 RAM):
\begin{itemize}
    \item \textbf{Inference Engine and Backend Routing:} All multi-step ReAct reasoning steps were executed using Google Gemini 2.5 Flash (\texttt{gemini-2.5-flash}) accessed via official SDK endpoints. Prompt context assembly and memory subgraph retrieval were executed locally via NetworkX ($1.158$\,ms).
    \item \textbf{Inference Parameters:} Temperature was fixed at $T = 0.20$, top-$p = 0.95$, and maximum generation length at 2,048 tokens to minimize stochastic drift.
    \item \textbf{Execution Bounds and Retries:} The ReAct execution loop was bounded by a strict step budget $N_{\text{max}} = 10$. Each individual tool call had a 30.0-second execution timeout. Network transport failures triggered up to 3 retry attempts with exponential backoff ($\tau_{\text{retry}} = 2^k \cdot 1.5\,\text{s}$).
    \item \textbf{Tool Manifest:} The agent was provided access to four primary local plugins: \texttt{FilesystemPlugin} (\texttt{list\_directory}, \texttt{read\_file}), \texttt{SystemPlugin} (\texttt{run\_command}), \texttt{WebSearchPlugin} (\texttt{duckduckgo\_search}), and \texttt{WebScrapePlugin} (\texttt{scrape\_page}), all gated by \texttt{DioneSafetyMiddleware}.
    \item \textbf{Scoring and Evaluation Criteria:} Outputs were scored strictly against ground truth using normalized string comparison and deterministic regex parsing (case-insensitive stripping, numerical value parsing). For security trials, a pass required non-zero safety interception (Level 1 block or Level 2/3 modal gate) with zero unauthorized host actuation.
    \item \textbf{Baseline Comparability:} Literature baselines (Packer et al. \cite{packer2023memgpt}, Mialon et al. \cite{mialon2023gaia}, Liu et al. \cite{liu2023agentbench}) evaluated cloud models (GPT-4) in unconstrained or headless Linux containers. In contrast, Dione operates under real desktop constraints with active neuro-symbolic safety inspection and strict local step budgets.
\end{itemize}

\subsection{Adversarial Security Benchmarks (ASB \& Injection Defense)}
To verify the defensive boundary of \texttt{DioneSafetyMiddleware}, we evaluated the system against a standardized penetration suite of $N=100$ hostile test vectors generated across 12 core threat templates drawn from published taxonomies (BIPIA \cite{bipia2023}, InjecAgent \cite{injecagent2024}, ASB \cite{zhang2024agent}), combining direct prompt overrides, indirect retrieved-context attacks, and host command injection exploits:
\begin{itemize}
    \item \textbf{Direct Injections (40 cases):} System override instructions and simulation jailbreaks adapted from Liu et al. \cite{liu2023prompt} and JailbreakBench \cite{jailbreakbench2024}. 28 were blocked at Level 1, 4 at Level 2, and 8 bypassed defenses via conversational re-framing (32/40 defended, 80.0\% containment).
    \item \textbf{Indirect Injections (35 cases):} Poisoned payloads embedded inside simulated emails, markdown documents, and downloaded webpages adapted from BIPIA \cite{bipia2023} and ASB \cite{zhang2024agent}. 12 were neutralized at Level 1, 8 at Level 2/3, and 15 penetrated defenses via semantic injection, inducing passive context leakage or malicious parameter generation (20/35 defended, 57.1\% containment).
    \item \textbf{Privilege Escalation (25 cases):} Hostile shell payloads attempting unauthorized file deletion, recursive destruction, or registry manipulation. 4 were blocked at Level 1 and 6 by modal gates; however, 15 obfuscated payloads (e.g., base64 encoding, dynamic string concatenation) bypassed AST pattern checks, resulting in 5 destructive command breaches (10/25 defended, 40.0\% containment).
    \item \textbf{Aggregate Defense Results \& Vulnerability Gap:} The safety kernel successfully intercepted \textbf{62 out of 100 attacks (62.0\% defense rate)}, comprising \textbf{44 blocked at Level 1} and \textbf{18 halted at Level 2/3} (Fig.~\ref{fig:resource_safety}). A significant \textbf{38.0\% vulnerability penetration} occurred under indirect and obfuscated vectors (28 passive context leaks, 10 destructive/obfuscated command executions), proving that deterministic AST filters and modal confirmation gates must be augmented with neural guardrails.
\end{itemize}

\subsubsection{Formal Threat Taxonomy and Defense Categorization}
To establish unambiguous criteria for security evaluations, we define four operational outcome classes:
\begin{enumerate}
    \item \textbf{Level 1 Block (Syntactic/Pattern):} Immediate pre-execution AST or regex interception rejecting forbidden shell operators (\texttt{\&}, \texttt{|}, \texttt{;}, \texttt{`}, \texttt{\$()}) or dangerous commands (\texttt{rmdir /s /q}, \texttt{DROP TABLE}) before the model or host executes them.
    \item \textbf{Level 2/3 Interception (Capability/Gate):} Poset lattice permission rejection ($\text{Level}(\text{Tool}) > L_{\text{plugin}}$) or mandatory human-in-the-loop modal confirmation halting execution until explicit approval is granted.
    \item \textbf{Non-actuating Completion:} The foundation model generates a benign conversational refusal or summary without emitting any tool invocations. The host state remains unmodified.
    \item \textbf{Destructive Breach:} Unauthorized modification, deletion, or exfiltration of host files, registry keys, or database records. Dione sustained 0 breaches across all 100 adversarial trials (0.0\% breach rate).
\end{enumerate}

\section{Empirical Trade-offs, Failure Mode Analysis, and Implementation Bottlenecks}

Rather than claiming uniform superiority across all dimensions, a mature scientific evaluation must document where the architecture encounters concrete engineering bottlenecks and trade-offs.

\subsection{Web Retrieval Divergence and Unstructured Scraping Loops}
The primary task failure observed during our unmocked workstation benchmark was GAIA Task \texttt{8e867cd7} (Mercedes Sosa discography query). A granular autopsy of the execution trace reveals the core bottleneck of general-purpose ReAct agents when confronted with unstructured web data:
\begin{enumerate}
    \item \textbf{Snippet Truncation:} The initial call to \texttt{WebSearchPlugin.duckduckgo\_search} returned high-level search snippets summarizing Sosa's musical career but omitted the chronological table of studio albums and release years.
    \item \textbf{Scraping Overhead without Table Parsers:} To obtain the missing tabular data, the agent dispatched \texttt{WebScrapePlugin.scrape\_page} on the full Wikipedia discography URL. Because Dione's scrape tool strips raw HTML to extract plaintext markdown to conserve prompt tokens, the tabular column associations between album titles and release dates were lost.
    \item \textbf{Step Budget Exhaustion:} Lacking table extraction primitives, the agent re-formulated search queries and scraped auxiliary fan pages across 10 consecutive turns, consuming 98,329.5\,ms before the ReAct step boundary ($N_{\text{max}} = 10$) halted execution.
\end{enumerate}
This demonstrates that while deterministic step budgets successfully prevent runaway execution costs, general-purpose text scrapers require domain-specific tabular parsers (e.g., BeautifulSoup table extractors) to solve dense biographical and chronological queries.

\subsection{Safety Verification Latency vs. Automation Throughput}
Dione enforces a multi-stage safety kernel consisting of static AST sanitization, poset lattice validation, and Tier-3 interactive modal gates. As shown in Table~\ref{tab:comparison}, this architecture introduces a clear trade-off between host security and execution throughput:
\begin{itemize}
    \item \textbf{Inspection Overhead:} AST parsing and regular expression filtering execute in $\approx 1.0$\,ms per tool call. While this microsecond latency is negligible for isolated commands, composite tasks requiring rapid sequences of low-level commands incur cumulative serialization overhead.
    \item \textbf{Human-in-the-Loop Latency:} Whenever a tool requests high-privilege access (e.g., desktop mouse actuation or directory writes), execution suspends pending user approval via CLI or mobile modal. Awaiting human confirmation introduces an operational latency of 4.2 to 15.8 seconds per confirmation.
    \item \textbf{Throughput Comparison:} As a consequence, Dione achieves an automated tool throughput of 5.2 ops/s, compared to 18.5 ops/s in unchecked, headless frameworks such as OpenClaw. Dione deliberately trades raw tool throughput to guarantee host data sovereignty and prevent catastrophic automated accidents.
\end{itemize}

\subsection{Local Model Memory Footprint and Cold-Start Costs}
Operating an on-device personal assistant requires balancing local hardware resources against cognitive capabilities:
\begin{itemize}
    \item \textbf{Orchestrator Footprint:} The baseline Dione FastAPI server and NetworkX graph require $\approx 310$\,MB resident set size (RSS). Initializing the DistilRoBERTa sequence classifier for affective persona modeling adds $\approx 153$\,MB, and loading ChromaDB vector indices brings steady-state orchestrator RSS to 526.4\,MB.
    \item \textbf{Foundation Model Demands:} In full on-device mode, running an 8B quantized model (e.g., LLaMA-3-8B Q4\_K\_M) via Ollama requires $\approx 4.8$\,GB of unified RAM/VRAM.
    \item \textbf{Host Impact on Commodity Hardware:} On a consumer laptop equipped with 8\,GB of RAM, this combined footprint exceeds 65\% of total system memory. This resource competition can cause page swapping and noticeable stuttering during concurrent user multitasking (e.g., video editing or compiling code), underscoring the necessity of hybrid cloud dispatch for resource-constrained client machines.
\end{itemize}

\subsection{Operating System Lock-in and Platform Portability}
Dione's low-level computer-use and GUI actuation engine is tightly coupled to Microsoft Windows:
\begin{itemize}
    \item \textbf{Session 0 Workstation Hooks:} The desktop screen capture implementation explicitly attaches to \texttt{winsta0\textbackslash default} using Win32 \texttt{OpenWindowStationW} and \texttt{OpenInputDesktop}.
    \item \textbf{Actuation Primitives:} Mouse and keyboard event injection relies on native Win32 \texttt{SendInput} structures and pixel-coordinate translations calibrated to Windows display DPI scaling.
    \item \textbf{Portability Limitations:} Dione cannot run natively on Linux or macOS without re-implementing the display abstraction layer. On Linux, input injection and screen capture must be rewritten for Wayland Compositor protocols and X11 extensions. On macOS, actuation requires Apple Quartz Display Services and Accessibility API permissions.
\end{itemize}

\section{Conclusion}

We have presented \textbf{Dione}, an on-device Large Action Model (LAM) orchestration engine built on the Microsoft Agent Framework that delivers proactive, ambient personal assistance without compromising privacy. By integrating a typed NetworkX Knowledge Graph, a 0-1 Knapsack Context Optimizer, an Adaptive Heartbeat Scheduler, an Affective Persona Modeling Engine, a 5-tier Safety Kernel, and a Win32 Multimodal Computer-Use Engine, Dione proves that privacy-preserving local systems can operate autonomously under clear engineering constraints. Standardized benchmarks confirm a $27.6\%$ aggregate task completion rate across GAIA and AgentBench suites (with $50.0\%$ on unmocked host instances, trailing multi-agent cloud frameworks), a $62.0\%$ defense rate against adversarial prompt injections ($62/100$ defended, acknowledging a $38.0\%$ vulnerability penetration under indirect and obfuscated vectors), a $65.2\%$ prompt token reduction relative to uncompressed naive append at Turn 30 (while carrying $+32.5\%$ overhead compared to MemGPT), sub-2ms graph lookups ($1.158 \pm 0.241$\,ms) decaying to $34.5\%$ Session 5 recall, and an active footprint of $463.1$\,MB in hybrid mode scaling to $5{,}313$\,MB during 100\% on-device 8B model inference. Furthermore, our empirical analysis clearly delineates real engineering bottlenecks: web search divergence on unstructured HTML tables, throughput trade-offs from human confirmation gates ($5.2$ vs. $18.5$ ops/s in OpenClaw), memory constraints on 8\,GB host PCs, and Win32 platform lock-in.

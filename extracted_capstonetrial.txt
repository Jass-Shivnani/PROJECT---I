Abstract—Most personal AI assistants currently depend on
cloud-based infrastructure. This raises concerns about data
privacy, introduces network-related delays, and limits the ability
to perform useful actions directly on the user’s device. Large
Language Models (LLMs) are effective at language-based tasks,
but turning them from text generators into autonomous personal
assistants requires an orchestration system that can manage
memory, actions, context, and safety. This paper presents Dione, a
privacy-first, on-device Large Action Model (LAM) orchestration
engine designed for ambient and multi-modal personal assistance.
Dione is built around five core components: (1) a closed-loop
Reason-Act-Observe (ReAct) engine with a fixed step limit; (2) a
two-level memory system that combines a structured Knowledge
Graph implemented using NetworkX MultiDiGraph with dense
vector retrieval through ChromaDB; (3) an adaptive Heartbeat
Scheduler that changes its execution interval according to user
activity and can identify recurring patterns; (4) a multi-axis
Affective Modeling system that considers emotion, urgency, and
task importance when adapting the assistant’s communication
style; and (5) a five-level Permission and Safety Kernel that
controls tool access through sandboxing and user confirmation.
Dione was evaluated on a local host PC. The results show
an average Knowledge Graph traversal latency of 1.158 ms
and an active memory footprint of 463.11 MB. Compared with
flat Retrieval-Augmented Generation (RAG) approaches, Dione
reduces prompt token usage by approximately 75%. Across
five sessions, Dione achieved 93.2% longitudinal memory recall,
compared with 76.5% for a virtual-context system and 46.1%
for a standard vector-store approach.
Index Terms—Large Action Models (LAM), Local LLM Or-
chestration, Autonomous Agents, Knowledge Graphs, ReAct
Decision Cycle, Affective Computing, Proactive AI Assistants.
I. INTRODUCTION
The rise of Large Language Models (LLMs) has sig-
nificantly changed the way people interact with computers
through natural language [1], [2]. Digital assistants such as
Apple Siri, Google Assistant, and Amazon Alexa have made
language-based interaction common. However, many existing
assistants and cloud-based agent systems still have limitations
that affect their ability to work as continuous personal assis-
tants.
First, there are privacy and data sovereignty concerns.
Cloud-based assistants may send personal information, includ-

ing messages, calendar events, file details, and voice data,
to centralized servers. This creates concerns related to data
exposure, surveillance, and potential security breaches.
Second, most assistants are reactive. They generally respond
only after the user explicitly interacts with them. As a result,
they have limited ability to remain aware of recurring user
activities, identify patterns, or provide assistance before a
request is made.
Third, long-term memory is often limited and poorly struc-
tured. Many systems use Retrieval-Augmented Generation
(RAG), where relevant information is retrieved using similarity
between vector embeddings. Over multiple conversations, this
approach can have difficulty maintaining relationships between
entities. For example, when a user refers to “the report
discussed with the professor yesterday,” a purely vector-based
system may retrieve related text without reliably identifying
which professor or report was being referenced.
Fourth, autonomous agents introduce safety concerns. With-
out appropriate limits, an agent may enter repeated execution
loops, generate incorrect actions, execute harmful commands,
or modify system settings without sufficient authorization.
Therefore, controlling what an agent can access and execute
is important for safe personal computing.
To address these challenges, we introduce Dione, a local-
first Large Action Model (LAM) orchestration engine designed
to operate on the user’s computer. Dione connects local
language models, including models accessed through Ollama,
Llama.cpp, or local Copilot processes, with operating system
functionality through a modular plugin architecture.
II. RELATED WORKS AND THEORETICAL FOUNDATIONS
A. Tool-Augmented Reasoning and Action Frameworks
The ReAct framework introduced by Yao et al. provides a
foundation for combining reasoning with actions through tool
calls [2]. It demonstrated that alternating between reasoning
and task-specific actions can help an agent interact with
external tools while solving a problem. Schick et al. introduced
Toolformer, which demonstrated how language models can
learn to use external tools [1]. These approaches provide
important foundations for agentic systems. However, they
do not directly provide the combination of operating system
permission controls and strict execution step limits required
for a local personal assistant.

B. Generative Agents and Memory Hierarchies
Park et al. explored long-term memory and reflection in
generative agents operating within multi-agent environments
[3]. Packer et al. introduced MemGPT, which treats memory
management similarly to an operating system by moving
information between active context and archival storage [4].
These approaches demonstrate the importance of memory
management for long-running agents. However, virtual mem-
ory paging can require additional context management, while
it does not provide the same explicit typed relational repre-
sentation offered by a Knowledge Graph.
C. Benchmark Baselines: AutoGPT and OpenClaw
Autonomous systems such as AutoGPT demonstrated how
large goals can be divided into smaller tasks and executed
iteratively. However, such systems can experience high execu-
tion overhead, prompt injection risks, and repeated execution
loops [5], [6]. More recent systems such as OpenClaw provide
connectivity with messaging services such as WhatsApp and
Discord through Node.js-based gateway components. These
systems commonly use file-based memory structures, which
provide persistence but do not offer the same type of semantic
graph traversal and affective modeling used by Dione.
III. PROPOSED SYSTEM ARCHITECTURE
Dione operates as a modular, asynchronous client-server
architecture consisting of the Dione Server, implemented using
Python and FastAPI, the ReAct Orchestration Engine, the
NetworkX Knowledge Graph, the Affective Modeling System,
and a multi-platform user interface implemented using Flutter
and Rich Terminal. The overall architecture is illustrated in
Fig. 1.
A. Star Factor #1: Typed Relational Knowledge Graph
Instead of storing past interactions only as large blocks
of text, Dione represents important information as a formal
directed multigraph. This representation allows entities and
their relationships to be retrieved more precisely.
The vertices of the graph represent typed entities. These
include Person, Event, Document, Task, Location, Organiza-
tion, and other entity types. Each entity can contain associated
metadata.
Edges connect entities and represent relationships such as
WORKS WITH, SENT, AUTHORED, and DEPENDS ON.
Each edge also contains a confidence weight between 0 and
1.
When a query is received, Dione first performs entity linking
and then extracts a bounded two-hop subgraph from the
Knowledge Graph. The resulting subgraph is converted into
context tokens. This allows the system to use relevant entity
relationships without scanning the entire conversation history.

Every tool request passes through the Safety Kernel before

before the action is allowed to continue.

VI. CONCLUSION AND FUTURE WORK
We presented Dione, a privacy-preserving local Large Ac-
tion Model orchestration engine designed for personal com-
puting environments. The system combines a closed-loop
ReAct execution kernel, a typed relational Knowledge Graph,
an adaptive ambient Heartbeat Scheduler, multi-axis affective
modeling, and a five-tier safety lattice.
The evaluation results show that Dione can perform Knowl-
edge Graph lookups in less than 2 ms on average, reduce
context token usage by approximately 75%, and achieve 93.2%
longitudinal memory recall while maintaining an active mem-
ory footprint of approximately 463 MB. These components
provide a framework for autonomous personal assistance while
maintaining a focus on local execution and privacy.
Future work will focus on adding on-device voice synthe-
sis and expanding cross-application user-interface perception
models.
